## 1. 系统概览
PurpleInk 采用「根 Next 应用」与「server/ Worker」两个独立进程树，各自拥有独立的 .env 文件与环境变量命名空间，运行时互不共享。AI 提供商密钥（API Key）在 Next 侧仅从 Postgres 加密存储读取，绝不回退到环境变量；Worker 侧则直接读 env。TTS 相关配置通过独立的 `config/tts.env.example` 与 `server/.env.example` 管理。

## 2. 核心文件与包
- 根环境模板：`.env.example` — 定义 Next 进程消费的环境变量（数据库、AI 端点、邮件 SMTP、反代 Basic Auth、演示账号等），secret 值留空
- Worker 环境模板：`server/.env.example` — 定义后端 worker 消费的环境变量（StepFun、IMAP、Playwright、ListenHub TTS、Gemini、阿里云 SMTP）
- TTS 配置模板：`config/tts.env.example` — ListenHub FlowSpeech TTS 专用配置
- 反向代理配置：`deploy/reverse-proxy/Caddyfile` — Caddy 2.10-alpine 反向代理，通过 Docker secrets 注入 Basic Auth 凭据
- 文档规范：`docs/configuration/credentials.md`、`docs/configuration/tts.md` — 凭据边界、冷启动流程、安全约束的权威说明

## 3. 架构设计
### 3.1 双进程隔离
- Next 应用：`pnpm dev` / `next start` 运行，读取根 `.env.local`（git 忽略），API Key 仅从 `provider_credentials` 表解密读取
- Worker 后端：`node server/src` 运行，依次加载 `server/.env` → 仓库根 `.env.local`（后者可覆盖同名键），所有配置直接从 `process.env` 读取
- 两个进程的 .env 文件「各自为政」，禁止交叉引用或统一 loader

### 3.2 环境变量加载机制
- Worker 启动入口 `server/src/index.ts` 调用自定义 `loadEnv()` 函数（`server/src/lib/load-env.ts`），按顺序加载 `.env` 和 `.env.local`，已存在的键不覆盖
- Next 应用使用 Next.js 内置的 `@next/env` 的 `loadEnvConfig(process.cwd())` 加载根目录环境变量
- bootstrap 脚本 `scripts/setup/bootstrap-credentials.ts` 通过 `Module._resolveFilename` shim 绕过 `'server-only'` 限制，直接加载 Next 业务模块进行凭据验证与写入

### 3.3 凭据分层策略
- **Next 侧 AI 凭据**：严格 DB-only，`apiKey` 字段全部从 `provider_credentials` 加密存储读取，无 env fallback（由 AGENTS.md §7 和契约测试双向锁定）
- **Next 侧非敏感配置**：如 `*_BASE_URL`、`*_MODEL` 等可通过环境变量覆盖代码默认值
- **Worker 侧配置**：纯 env 驱动，启动时直接读取 `process.env`
- **TTS 配置**：Worker 侧使用 ListenHub FlowSpeech，Next 侧支持 MiMo、StepFun 及 OpenAI 兼容端点，两者实现完全独立

### 3.4 冷启动引导流程
1. 生成 master key：`pnpm tsx scripts/migration/provision-master-key.ts --env .env.local`
2. 执行数据库迁移：`pnpm db:migrate`
3. 手动复制 API Key 值到根 `.env.local`（从 `server/.env` 复制）
4. 运行凭据引导：`pnpm tsx scripts/setup/bootstrap-credentials.ts`
5. 启动应用：`pnpm dev`（运行时不再读取 .env 中的 API Key）

## 4. 约定与约束
- **安全约束**（AGENTS.md §7 强制）：secret 类变量值必须留空，真实值只写在被忽略的 `.env.local`，禁止提交、禁止硬编码进源码
- **禁止 NEXT_PUBLIC_* 携带 secret**：任何包含密钥的 `NEXT_PUBLIC_*` 变量会被构建期内联到客户端 bundle
- **双存储隔离**：Next 与 Worker 的 .env 文件保持分离，禁止引入统一 loader 或共享环境变量
- **API Key 不回退**：Next 侧运行时绝对不允许 `process.env.GEMINI_API_KEY ?? storedKey` 这样的明文回退模式
- **Bootstrap 幂等性**：bootstrap 脚本失败不会覆盖现有加密行，校验失败返回非 0 退出码
- **设置页更新路径**：运行时只能通过 `POST /api/settings` 更新凭据，先验证后保存，GET 接口不返回 apiKey 字段
- **TTS 配置独立性**：Next 与 Worker 的 TTS 实现完全解耦，Worker 侧不读 `provider_credentials`，也不消费 Next 的配置
- **Caddy 反向代理**：Basic Auth 凭据通过 Docker secrets 注入，未设置时取证脚本行为与之前一致（不发该头）
