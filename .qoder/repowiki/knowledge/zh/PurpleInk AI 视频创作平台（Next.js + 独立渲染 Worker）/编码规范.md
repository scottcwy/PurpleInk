- features 下每个业务域以 index.ts 作为聚合入口，domain、repository、client adapter、schemas、tests 同目录组织，形成自包含的领域边界。
- 所有外部输入与配置均通过 zod schema 校验，配置文件与运行时参数成对出现 *.config.ts + *.config.test.ts。
- 数据库访问统一走 drizzle-orm，测试文件以 .pg.test.ts 后缀区分需要 PostgreSQL 的集成测试，并通过 vitest.pg.config.ts 单独运行。
- 服务端日志通过统一的 logger（server/src/lib/logger.ts 与 src/lib 下的 logger）输出结构化信息，错误经分类后仅暴露诊断摘要给用户。
- 组件与工具函数遵循 demo/test 分离：*.demo.tsx 用于 Storybook 或本地预览，*.test.ts(x) 覆盖核心逻辑，公共 UI 放在 components/ui 并附带 demo 文件。
- 环境变量通过 load-env 模块集中管理，.env.example 与 config/*.env.example 保持键名一致，敏感凭据通过 credential-envelope 封装。
