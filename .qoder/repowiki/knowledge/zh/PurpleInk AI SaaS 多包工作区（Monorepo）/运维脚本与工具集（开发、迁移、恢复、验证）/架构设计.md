scripts 目录按职责划分为五个互不依赖的子目录：
- `admin/`：一次性管理命令，如生成兑换码。
- `dev/`：Windows PowerShell 开发启动器（`start-dev.ps1`/`.cmd`），按固定顺序检查工具链、环境变量、Docker Postgres、pnpm 依赖、执行迁移并拉起 Next + worker，最后通过 HTTP probe 确认就绪。
- `migration/`：只读 SQLite → Postgres 的导出/导入/对账/备份脚本，所有源路径通过 `--source`/`--snapshot` 等 CLI 参数显式传入，禁止从应用配置推导。
- `recovery/`：针对运行中项目的恢复工具，先采集安全快照再可选地应用 SQL 修复，输出带 SHA-256 rowHash 的 JSON 审计文件。
- `setup/`：环境初始化入口（`db-migrate.ts`、`bootstrap-credentials.ts`、`seed-owner-account.ts`），通过 `@next/env` 加载 `.env.local` 后调用 `src/lib/db/migrate` 显式执行迁移。
- `verify/`：E2E 冒烟、认证流程取证、截图基线比对、架构文件限制检查等验证脚本，统一通过 `loadEnvConfig` + `server-only-stub.js` 绕过 Next 运行时限制直连数据库。

所有脚本均为独立可执行文件，通过 `process.argv` 解析 `--flag value` 形式的参数，使用 `if (process.argv[1] === fileURLToPath(import.meta.url))` 或 PowerShell 的 `CmdletBinding()` 作为入口守卫，错误时写入 stderr 并设置 `process.exitCode = 1`。模块间无相互 import，仅共享 `src/` 下的业务库（通过动态 `import(...)` 避免在 Node 环境下触发 `server-only` 哨兵）。
