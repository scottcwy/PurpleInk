模块以 `api.ts` 为入口，使用 `createServer` 监听端口并通过 `handle` 函数按路径分派路由：`/health`、`/render`、`/jobs`、`/jobs/:id` 及 `/jobs/:id/video`；`/internal/*` 路由由 `internal-api.ts` 统一拦截处理，先经 `internal-auth.ts` 的 `verifyInternalEngineKey` 校验 `PURPLEINK_ENGINE_INTERNAL_KEY`（支持 Bearer 或 `x-purpleink-engine-key` 头），再交由 `internal-render-request.ts` 做白名单字段校验、URL 策略验证与幂等指纹生成。

职责分层清晰：
- `job-store.ts` 维护进程内 `Map` 存储 Job 状态，提供 `createJob`、`createIntegratedJob`（基于 requestId 幂等复用）、`updateJob`、`toPublicJob`、`toIntegratedJobView` 等访问器。
- `job-runner.ts` 负责 fire-and-forget 执行：根据 `job.kind` 选择 `urlToVideo` 或 `renderFromCapture`，通过 `AbortController` 支持取消，阶段回调 `onPhase` 回写进度。
- `internal-render-request.ts` 定义 `NormalizedInternalRenderRequest` 类型与 `normalizeInternalRenderRequest` 校验器，强制 `credentialMode: 'none'`、`publicOnly: true`，并通过 SHA256 生成请求指纹用于去重。

依赖方向单向：`api.ts` → `internal-api.ts` / `job-store.ts` / `job-runner.ts`；`internal-api.ts` 仅依赖认证与请求规范化，不直接暴露给外部调用者。
