模块基于 Next.js App Router 的目录路由：`page.tsx` 作为各分类入口（根索引、`/playbook/ui`、`/playbook/icons`、`/playbook/foundations`、`/playbook/motion`），通过 `registry.ts` 中统一的 `PLAYBOOK_ENTRIES` 登记表 + `entriesByCategory()` 筛选函数驱动 UI 与 Icons 页面的渲染，Demo 组件由上游 `@/components/ui/*.demo` 和 `@/features/navigation/*.demo` 动态注入，形成「注册表 → 页面 → Demo」的单向依赖。

- `registry.ts` 是核心数据层，定义 `PlaybookEntry` 类型与 `PlaybookCategory`，集中维护所有可展示组件族及其元信息，并导出 Pencil 资产统计常量。
- `motion/` 子目录独立于通用 UI 注册表，采用「意图声明 (`motion-intents.ts`) → 标本展示 (`intent-specimens.tsx`, `specimen-stage.tsx`) → 交互控制 (`specimens-controls.tsx`, `specimens-overlays.tsx`) → 布局 (`specimens-layout.tsx`)」的分层结构，并通过 `countMotionIntents()` 暴露迁移状态统计给 `page.tsx`。
- `foundations/` 仅包含静态 token 展示与 `motion-tokens-section.tsx` 动效 token 区块；`icons/page.tsx` 与 `ui/page.tsx` 复用同一模板渲染对应分类条目。
- 测试集中在 `registry.test.ts`（校验登记数量与客户端边界）与 `motion/motion-intents.test.ts`（验证意图数据一致性）。
