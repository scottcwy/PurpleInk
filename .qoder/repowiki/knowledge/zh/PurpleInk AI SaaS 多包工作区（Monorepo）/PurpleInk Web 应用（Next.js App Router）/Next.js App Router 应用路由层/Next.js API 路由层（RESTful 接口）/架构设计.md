每个目录对应一个 URL 路径段，采用 Next.js App Router 的文件路由约定：`route.ts` 定义 HTTP 方法处理器（GET/POST/DELETE），`[id]` 或 `[nodeId]/[projectId]` 表示动态参数段。
- 入口层职责单一：仅负责解析请求体、参数校验、错误投影与返回 `NextResponse.json`，业务逻辑全部下沉到 `@/features/*` 包。
- 鉴权统一通过 `withApiSession` HOC 包裹异步处理器，确保所有写操作和受保护资源均需登录态。
- 错误处理分层：领域异常（如 `ProjectWorkflowStartError`、`ProjectCreateInputError`）直接映射为 `{ ok, code, error }` 结构；非领域异常经 `classifyWorkflowError` 投影为统一格式。
- 请求体验证使用 Zod schema（`z.object(...).strict()`）或共享 schema（如 `loginSchema`、`stepfunSettingsSchema`），失败时返回 400。
- 所有路由显式声明 `export const dynamic = 'force-dynamic'`，禁用静态生成以保证每次请求读取最新会话状态。
- 测试文件与路由文件成对存在（`route.test.ts`），便于单元测试覆盖。
