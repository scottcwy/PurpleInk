模块以 `client.ts` 作为进程内单例连接入口（`getDb()` 惰性创建并复用 postgres-js 客户端，失败后清理 rejected Promise 支持重试），通过 `drizzle(client, { schema })` 注入类型化 Schema 生成 `Db`/`PostgresDb` 类型。
- `schema/` 目录按领域拆分表定义（core、auth、canvas、execution、billing、ai、provider-dispatch、concurrency、project-sources、project-creation、telemetry、artifacts），由 `schema/index.ts` 统一 re-export，形成单一 Schema 聚合根。
- `migrations/pg/` 存放按编号命名的 SQL 迁移文件，配合 `meta/_journal.json` 管理版本顺序；`migrate.ts` 提供独立迁移执行入口，使用专用单连接并在 finally 中关闭。
- `transaction.ts` 暴露 `withTransaction` 包装器与 `TransactionContext` 类型，将 Drizzle 原生事务 API 收敛为应用级原子提交边界。
- `node-execution-fence.ts` 实现节点执行围栏，在事务内通过 `SELECT ... FOR UPDATE` 锁定 attempt 并校验 execution epoch，防止并发竞态。
- `test/pg-test-database.ts` 提供测试用 PG 数据库工厂，通过 advisory lock 保证多进程测试隔离，自动 reset schema 并运行迁移。
- `integration/` 下所有 `.pg.test.ts` 使用共享测试数据库执行端到端验证。
依赖方向：业务代码仅依赖 `index.ts` 导出的 `getDb`、`withTransaction`、Schema 导出与类型；不直接感知 drizzle/postgres 细节。
