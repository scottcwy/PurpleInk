模块以 `InProcessQueue`（`in-process-queue.ts`）为核心类，实现 `QueueAdapter` 接口并通过 `singleton.ts` 暴露全局单例 `queue`；`index.ts` 仅重导出公共 API，避免加载数据库依赖。

分层结构：
- 入口与生命周期：`init.ts` 通过 `globalThis` 锚点幂等注册各 feature 的 queue-handler 并启动消费循环；`singleton.ts` 用 `globalThis.__cvcQueue` 防止 HMR 多实例。
- 执行引擎：`in-process-queue.ts` 维护三个定时器——200ms 消费 tick、`HEARTBEAT_INTERVAL_MS` 续租、`SWEEP_INTERVAL_MS` 清扫；按 lane 配额并发拉取作业，失败走 `attempt-completion.ts` 的事务收尾。
- 持久化与租约：`lease.ts` 定义 LEASE_DURATION_MS、执行超时映射、心跳续租与 `sweepExpiredLeases` 事务回收；`attempt-completion.ts` 在事务中决定自动重试、Provider 限流等待或终态落库。
- 重试策略：`retry-policy.ts` 提供指数退避 + 抖动、窗口内指纹失败计数与 `assertEnqueueRetryBudget` 毒任务闸门。
- 配置：`runtime-config.ts` 实现 DB > env > 默认 的 lane 配额真值链，`lane-quota-env.ts` 解析环境变量，`queue-defaults.ts` 提供代码默认。
- 辅助：`execution-cancellation.ts` 用 AbortController 映射 attemptId→信号；`query.ts` 提供跨 workspace 隔离的作业快照查询；`provider-wait-scheduler.ts` 处理 Provider 排队等待。

依赖方向单向向外：queue 通过动态 `import()` 按需加载 features 子模块（director、render、audio、website、billing、canvas），避免 lib/queue 与 features 的静态循环依赖。所有 DB 操作经 `@/lib/db/client` 获取连接，使用 drizzle-orm 构建 SQL。
