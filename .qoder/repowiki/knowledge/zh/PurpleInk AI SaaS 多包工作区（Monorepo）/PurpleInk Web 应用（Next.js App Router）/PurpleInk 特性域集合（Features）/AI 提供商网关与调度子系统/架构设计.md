模块以 `index.ts` 作为对外统一导出入口，内部按职责划分为若干子层：
- 提供商注册与能力声明：`provider-registry.ts` 集中定义 `AI_PROVIDER_IDS`、`ProviderDefinition` 与 `assertProviderCapability`，所有 provider id 均从此枚举派生。
- 配置与凭据：`config.ts`、`mimo-config.ts`、`gemini-config.ts`、`openai-compatible-config.ts` 等通过 `AiConfigDependencies` 注入 `credentials`、`modelRoutes`、`mediaRoutes`、`fallbackProviders`、`managedModelCatalog`、`providerFunding` 等存储依赖，默认构造器使用 `Postgres*Store` 实现。
- 托管网关：`managed-gateway.ts` 的 `ManagedAiGateway` 是调用入口，根据 `fundingForProvider` 决定走 BYOK（直接加载用户 Key）或托管路径（`requireManagedCredential` + 费率卡预估 + 预留 `reserveManagedInvocation`），并通过 `invocation-handles.ts` 返回 `ManagedAiHandle` 生命周期对象。
- 调用记账：`invocation-ledger.ts` 记录未计费/已计费调用；`managed-service.ts` 负责授权校验与错误类型；`managed-vision-executor.ts`、`stepfun-adapter.ts`、`gemini-adapter.ts`、`mimo-adapter.ts` 分别封装具体上游协议。
- 调度与池控制：`provider-dispatch.ts` 基于 Drizzle ORM 对 `provider_dispatches`、`provider_pool_states`、`provider_dispatch_cooldowns` 表做事务性排队、冷却、公平性与速率窗口控制，配合 `provider-pool-control.ts` 自适应调整并发度，`provider-dispatch-window.ts`、`provider-dispatch-ticket.ts`、`provider-dispatch-cooldown.ts`、`provider-dispatch-scope.ts` 拆分窗口计算、票证激活、冷却与 scope key 生成。
- 工作区并发：`workspace-concurrency.ts` 基于 `workflowConcurrencyLeases` 表实现按 workspace/project/workUnitKey 的分镜槽位申请与 stagger 控制，受 `concurrency-rollout.ts` 的灰度开关影响。
- 设置与校验：`schemas.ts` 用 Zod 统一定义 `stepfunSettingsSchema`、`laneQuotasSchema` 等输入契约；`provider-settings-*` 系列文件处理设置投影、验证、BYOK/托管分支。
- 依赖方向单向：上层（gateway/调度）依赖下层（config/adapter/store），不反向引用；所有 DB 访问经 `@/lib/db/client` 的 `getDb()` 获取，且大量文件顶部标注 `'server-only'` 限制服务端使用。
