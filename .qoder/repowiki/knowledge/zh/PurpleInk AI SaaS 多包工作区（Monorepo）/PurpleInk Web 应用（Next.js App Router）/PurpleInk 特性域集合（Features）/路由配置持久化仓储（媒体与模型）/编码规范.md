- 每个仓储类通过构造函数注入 `DatabaseProvider` 与 `ProviderCredentialStore`，避免直接依赖全局单例。
- 输入参数统一经过 `assertTaskKind` 断言与 `required` 校验函数处理，再交给 Drizzle ORM 执行。
- CRUD 方法命名保持一致：`save`、`find`、`resolve`、`remove`，其中 `resolve` 总是先查路由再合并凭据。
- 写操作使用 `insert(...).onConflictDoUpdate({ target: [workspaceId, taskKind], set: { revision: sql`${table.revision} + 1`, updatedAt: new Date() } })` 实现版本自增的幂等更新。
- 类型定义成接口（`MediaRoute`/`ModelRoute`）配合 `Resolved*Route extends *Route` 扩展 secret 字段，枚举类型从 schema 常量推导 `(typeof X)[number]`。
