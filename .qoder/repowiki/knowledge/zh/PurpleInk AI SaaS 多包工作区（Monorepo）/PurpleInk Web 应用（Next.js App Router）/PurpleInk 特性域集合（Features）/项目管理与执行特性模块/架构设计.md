模块以 `index.ts` 作为统一导出入口，按职责拆分为多个独立文件：
- 数据访问层：`project-cards.ts`、`project-source-repository.ts`、`project-execution-snapshot.ts` 等通过 Drizzle ORM 直接查询 `projects`、`canvasNodes`、`artifacts`、`taskAttempts` 等表，并使用 `withTransaction` 包裹事务边界。
- 业务逻辑层：`project-creation.ts`、`project-deletion.ts`、`project-rename.ts`、`project-workflow-start.ts`、`project-execution-stop.ts`、`project-execution-recovery.ts` 各自封装一个原子操作，依赖注入 `database`、`workspaceId`、`storage` 等上下文。
- 契约与推导层：`project-execution-contract.ts` 定义 `ProjectExecutionSnapshot` 类型，`project-execution-derive.ts` 纯函数推导状态，`execution-client.ts` 用 Zod 校验 API 响应。
- 客户端交互层：`use-project-execution.ts` 基于 `SingleFlightExecutionReader` 和 `ExecutionSnapshotRevisionGate` 实现去抖轮询与版本门控；`execution-sync.ts` 提供并发控制。
- UI 组件：`project-cards-client.tsx`、`project-table.tsx`、`project-list.tsx`、`project-search-flyout.tsx`、`project-context-menu.tsx`、`project-mutation-dialogs.tsx` 等 React 组件仅消费上述服务接口。
依赖方向严格单向：UI → client hooks → execution-client → server-only 服务函数 → Drizzle ORM / storage 适配器，跨模块依赖通过 `@/lib/db/client`、`@/lib/auth/workspace-context`、`@/lib/workflow/project-workflow-registry` 等共享库注入。
