- 所有数据库操作都通过 `withTransaction` 或显式 `database.transaction` 包裹，并使用 `for('update')` 行锁防止并发覆盖，失败时抛出明确中文错误消息。
- 对外输入一律用 Zod schema 校验（如 `exportSettingsPatchSchema`、`exportSettingsSchema`、`canvasNodeTypeSchema`），非法输入回退默认值或直接抛错，不信任原始 JSON。
- 所有 DB 查询必须同时附加 `workspaceId = currentWorkspaceId()` 和 `projectId` 条件，确保租户与项目级隔离。
- 节点状态变更通过 `transitionNodeStatus` 单一入口进行，严格遵循 `ALLOWED_TRANSITIONS` 映射表，禁止直接更新 `canvasNodes.status`。
- 错误分类采用三段式策略：先按 Error.name 做类型匹配，再按正则规则匹配 message，最后按 stage 兜底，且不在错误信息中泄露凭据或 provider 响应。
- ID 生成使用 `stableId(kind, ...parts)` 基于 sha256 截断并注入版本位，保证跨进程幂等且不重复。
