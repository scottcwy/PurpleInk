模块以 `index.ts` 作为对外唯一入口，按职责拆分为多个独立文件：
- 类型与契约：`types.ts` 定义 `Project`、`CanvasNode`、`CanvasEdge`、`NodeStatus` 及各类 `*NodeType`；`contracts.ts` 重新导出这些类型并补充 `ShotLaneSeed`、`fabricate-source-contract`、`shot-revision` 等跨子模块共享契约。
- 数据访问层：`queries.ts`（读）、`actions.ts`（写）通过 Drizzle ORM 操作 `projects`、`canvasNodes`、`canvasEdges`、`artifacts` 表，所有查询均强制附加 `workspaceId` 与 `projectId` 过滤，使用 `currentWorkspaceId()` 做租户隔离。
- 状态机：`status.ts` 维护 `ALLOWED_TRANSITIONS` 有限状态机，通过 `withTransaction` + `for('update')` 原子校验转换、写入 `data.payload`，并在事务提交后通过 `statusBus` 发布事件；`status-payload.ts` 负责 payload 序列化/反序列化。
- 布局：`layout.ts` 基于 `@dagrejs/dagre` 计算 DAG 坐标，支持全局节点与按 `laneKey` 分组的泳道布局，坐标不持久化、每次渲染派生。
- 扇出：`fan-out.ts` 在单事务内幂等物化分镜通道（5 种 `ShotLaneNodeType`），连接 `shot-split` 与 `score` 锚点，并通过 `registerWorkflowSlotsInTransaction` 注册并发槽位。
- 错误分类：`workflow-error.ts` 将任意异常投影为 `WorkflowErrorProjection`，按「类型→文案→阶段」三段判定，避免反向依赖 director/features/ai；`workflow-fault-display.tsx` 与 `workflow-fault.ts` 提供展示与基础类型。
- 导出设置：`export-settings.ts` 集中分辨率预设、字幕模式与 zod schema，被 render/director/canvas 三方共享以避免循环依赖。
- 辅助：`content-hash.ts` 计算内容指纹用于 stale 检测，`node-error-projection.ts` 解析 director/render 错误，`director-ingest-source.ts` 声明进入 Director 链路的入口节点类型。
依赖方向单向向外：本模块依赖 `@/lib/db/*`、`@/lib/stream/status-bus`、`@/lib/auth/workspace-context`、`@/features/projects/project-compatibility`、`@/features/ai/workspace-concurrency`，不被 features 内部其他模块反向依赖。
