模块以 `index.ts` 作为对外统一导出入口，内部按职责拆分为若干独立文件：
- 输入/输出类型集中在 `types.ts`，所有外部 API 的入参均通过 zod schema 校验（如 `audioTranscriptionJobSchema`、`inputSchema`）。
- 媒体供应商抽象在 `media-provider.ts`，通过 `resolveProvider` + `MEDIA_PROVIDERS` 枚举实现 stepfun/mimo/openai-compatible 多后端路由，并由 `managed-audio-billing.ts` 统一走 `ManagedAiGateway` 进行授权、预留、哈希与结算。
- 工作流编排层由 `audio-transcription-job.ts` 驱动 INGEST 阶段：加载源→解码→ASR→构建时间线→切片→持久化→推进下游；状态机通过 `AudioTranscriptionState` 联合类型表达 running/waiting/ready/failed。
- 旁白合成 `narration.ts` 使用内容寻址键 `narrationAudioKey` 避免重复计费，并发通过 `NARRATION_CONCURRENCY=4` 的 worker 池控制。
- 用户音频时间线 `user-audio-timeline.ts` 将 ASR 字幕时间戳聚合为稳定的 script units 与采样边界，不可用时回退到整段录音模式。
- 运行时数据访问由 `runtime-repository.ts` 的 `AudioRuntimeRepository` 封装，基于 drizzle-orm 查询 artifacts 表并校验存储一致性。
- 依赖注入采用函数参数传入 dependencies 对象（如 `AudioTranscriptionDependencies`、`NarrationDependencies`），默认值通过 `defaultDependencies()` 工厂提供，便于测试替换。
- 底层格式解析由 `audio-format.ts`、`mp3-frame-header.ts`、`wav-header.ts` 等文件分别处理不同容器格式。
