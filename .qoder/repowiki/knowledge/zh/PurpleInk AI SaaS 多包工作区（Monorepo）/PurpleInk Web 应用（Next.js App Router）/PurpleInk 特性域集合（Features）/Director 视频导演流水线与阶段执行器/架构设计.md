模块以 `types.ts` 定义的 `PIPELINE_STAGES` 为常量入口，`pipeline.ts` 提供有序 StageMeta；核心执行流由 `stage-runner.ts` 的 `createStageRunner` 通过依赖注入组装：repository（`runtime-repository.ts` 封装 Postgres + Storage）、session（`pi-session.ts` 基于 `@earendil-works/pi-agent-core` 的 Agent）、prompt builder（`stage-prompt.ts` 及各阶段 prompt 文件）、artifact writer（`tools/write-artifact.ts`）和副作用钩子。

- 推进层：`advance.ts` 暴露 `advancePipeline`/`startProjectPipeline`，仅消费 DAG 与 autopilot 标志，通过 `AdvanceRepository`/`PipelineRepository` 接口解耦数据库访问。
- 运行时仓库：`DirectorRuntimeRepository` 统一读写 `canvasNodes`/`artifacts`/`taskAttempts`，并通过 `DirectorArtifactReader`/`DirectorArtifactWriter` 分离读写路径，所有写操作经 `withTransaction` 保证原子性。
- AI 会话层：`pi-provider.ts` 按节点类型+阶段路由到 Gemini/OpenAI 兼容端点，`pi-session.ts` 装配 ManagedAiGateway、计费流、熔断与重试（429 deferProviderScope），`pi-stream-bridge.ts`/`pi-tool-adapter.ts` 桥接工具调用与流式输出。
- 产物治理：`stage-artifact-gate.ts` + `tools/write-artifact.ts` 对 non-empty/shot-plan/deterministic-html 三类产物做 Zod 校验与内容哈希，失败抛 `ArtifactValidationError`。
- 特殊入口：`fabricate.ts` 为 shot-codegen 提供不改变节点状态的独立 runner；`export-finalization.ts`、`final-export-artifact-source.ts` 处理导出终稿。
- 恢复与并发：`recovery.ts`、`frontier-lock.ts`、`frontier-reconciliation.ts`、`output-recovery.ts` 提供断点续跑、前沿修复与锁机制；`queue-handler.ts`、`cancel-wait.ts` 对接队列与取消语义。
- 依赖方向单向向下：stage-runner → repository/session/tools/prompts/schemas，不反向引用上层 features。
