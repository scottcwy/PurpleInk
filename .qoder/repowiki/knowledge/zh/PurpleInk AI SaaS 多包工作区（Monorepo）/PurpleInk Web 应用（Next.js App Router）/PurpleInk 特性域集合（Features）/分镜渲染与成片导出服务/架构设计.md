模块以 `index.ts` 为对外入口，统一暴露 `HyperframesRenderer`、`RenderRepository`、队列入队/处理器以及缩略图 API。

- 核心流水线：`renderer.ts` 中的 `HyperframesRenderer` 遵循 guard → cache → capture → encode → commit 顺序，依赖注入 `StorageAdapter`、`lookupCache`/`writeCache`、`captureSequence`、`encode` 和临时目录，确保渲染过程可测试且无副作用。
- 缓存层 `cache.ts` 基于 artifacts 表按 `render/${projectId}/${nodeId}/${renderKey}.mp4` 键查找/登记内容寻址 MP4，并在写入时校验实际 hash 与声明一致。
- 队列层 `queue-handler.ts` 提供 `registerRenderShotHandler`（注册 'render-shot' 任务）和 `enqueueRenderShot`（入队前做 admission 检查、重试预算闸门、节点状态推进），失败通过 `queue-failure-compensation.ts` 补偿。
- 持久化层 `repository.ts` 继承 `RenderArtifactRepository`，负责导出计划计算、shot QA 投影读写、降级导出检测；依赖 `media-assembly-loader.ts` 组装时间轴。
- 导出服务 `export-service.ts` 编排 concat、字幕 ASS 生成、SFX 清单存储与最终产物注册，使用 `ExportExecutionError` 包装各阶段错误。
- 辅助子模块按职责拆分：`frame-capture.ts`/`frame-sequence.ts`（帧捕获）、`encode.ts`/`concat.ts`（FFmpeg 编码/拼接）、`thumbnail.ts`（缩略图 PNG 生成与路径约定）、`qa-check.ts`/`vision-qa.ts`（黑帧/纯色与视觉 AI QA）、`procedural-sfx-*`（程序化音效）、`final-output-storage.ts`/`final-video-delivery.ts`（终片存储与交付模式）、`admission.ts`/`source-contract.ts`（入队准入与确定性源校验）。
- 类型集中在 `types.ts`，所有跨文件共享的结构体（FrameSpec、RenderJob、ThumbnailResult、VisionQaReport 等）均在此定义，避免循环依赖。
- 依赖方向单向向外：本模块依赖 `@/lib/storage`、`@/lib/db`、`@/features/artifacts`、`@/features/canvas`、`@/features/projects`、`@/lib/queue`，不被其他 render 子模块反向引用。
