- 所有写数据库的操作都包裹在 database.transaction 中，并通过 for('update') 锁定相关行或使用 pg_advisory_xact_lock 防止并发冲突。
- 业务异常统一继承 Error 并声明 readonly code 与 name 属性（如 QuotaExhaustedError、BillingIdempotencyConflictError），便于上层区分处理。
- 金额与配额一律使用 bigint（CNY Micros）表示，避免浮点精度问题，并在输入处显式校验非负性。
- UI 层通过独立的 projection-contract.ts 定义 BillingUiProjection 白名单字段，禁止将内部成本池或单价字段泄露给前端。
- 幂等性通过 idempotencyKey + requestFingerprint 双重校验：先查审计表比对指纹，再返回历史结果或抛出 BillingIdempotencyConflictError。
- 文件按单一职责拆分（domain/contracts/ledger/period-service/rate-card/redemption），并通过 index.ts 集中 re-export 对外 API。
