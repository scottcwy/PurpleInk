本模块是 PurpleInk 的 Next.js 应用壳层，采用分层组合模式：
- 根 `src/app/layout.tsx` 作为唯一入口，注入字体、主题模式脚本、`AppMotionConfig`、`RootProviders` 与 SkipToContent，所有子路由共享同一 React 上下文与全局样式。
- `src/instrumentation.ts` 在 Node.js 进程启动时初始化进程内队列（`initQueue`），并通过 `globalThis` 锚定状态，确保 API 路由首次请求可兜底重试，避免 split-brain。
- `app/` 下按功能域划分路由组：`(auth)` 认证流程、`(marketing)` 营销落地页、`(public)` 公开页面、`products/(app)` 产品应用、`playbook` 设计系统手册；每个组自带 layout.tsx 提供局部壳。
- `api/` 下的 RESTful 路由全部委托 `features/` 中对应业务域实现，形成「路由层 → features 域 → lib 基础设施」的单向依赖。
- `components/` 提供跨路由复用的 UI 原子组件与营销区块，`lib/` 提供跨模块共享能力（auth/db/stream/queue/storage/workflow/determinism/motion/hooks 等），被 app_routes、api_routes 与 features 共同消费。
- 构建期通过 `next/font/local` 自托管 Geist 字体，避免 Docker 构建阶段访问 Google Fonts 失败。
