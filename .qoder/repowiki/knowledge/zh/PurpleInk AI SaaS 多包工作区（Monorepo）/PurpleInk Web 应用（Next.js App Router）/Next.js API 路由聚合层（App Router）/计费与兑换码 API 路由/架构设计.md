基于 Next.js App Router 的 Route Handler 组织：`route.ts` 暴露 GET 用于获取计费投影（调用 `@/features/billing.getBillingProjection`），`redemptions/route.ts` 暴露 POST 用于兑换码兑换（调用 `redeemBillingCode`）。两个路由均通过 `withApiSession` HOC 注入 `{ userId, workspaceId }` 会话上下文，并以 `dynamic = 'force-dynamic'` 禁用静态生成。请求处理采用薄适配层模式：解析 JSON 与 idempotency-key → 参数校验 → 调用领域服务 → 将领域错误码（如 `forbidden`、`redemption_conflict`、`idempotency_conflict`、`code_unavailable`）映射为统一的 `{ ok, error }` JSON 响应与对应 HTTP 状态码（400/403/409）。测试文件使用 vitest + vi.mock 对 `@/features/billing` 和 `@/features/auth/api-session` 进行隔离模拟。
