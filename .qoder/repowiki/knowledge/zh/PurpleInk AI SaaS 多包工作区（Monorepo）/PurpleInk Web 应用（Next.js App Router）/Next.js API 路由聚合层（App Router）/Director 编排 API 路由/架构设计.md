基于 Next.js App Router 的目录即路由结构：`pipeline/route.ts` 暴露 POST/DELETE 启动或停止项目流水线；`stage/route.ts` 通过 `intent` 字段分发到 `executeNodeAction`/`skipNodeAction`/`cancelProviderWaitAction`；`stream/[nodeId]/route.ts` 和 `stream/project/[projectId]/route.ts` 分别按节点和项目维度建立 SSE 通道。所有路由统一通过 `withApiSession` 进行鉴权包装，并通过 `initQueue()` 懒初始化队列。请求体校验使用 Zod schema（`requestSchema`），错误处理遵循模式：先匹配业务异常（如 `ProjectWorkflowStartError`、`QuotaExhaustedError`、`SkipRejectedError`），再经 `classifyWorkflowError({ stage: 'QUEUE' })` 投影为统一 `{ ok, code, error }` 响应。SSE 实现基于原生 `ReadableStream` + `TextEncoder`，通过 `streamBus` / `statusBus` 事件总线订阅，并配合 `runInAuthContext` 在回调中重建认证上下文。
