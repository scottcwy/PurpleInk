模块以 Next.js App Router 的目录路由组织：`page.tsx` 为入口索引，`foundations/`、`ui/`、`icons/`、`motion/` 各为一个分类页。
- `registry.ts` 是 UI 组件族的单一登记中心，通过 `PlaybookEntry` 接口把来自 `@/components/ui/*.demo` 和 `@/features/navigation/collapsible-panel.demo` 的 Demo 组件统一注册，并由 `entriesByCategory()` 供 `ui/page.tsx`、`icons/page.tsx` 渲染。
- `motion/` 子模块采用「登记表 + 标本映射」双层结构：`motion-intents.ts` 定义 `MotionIntent` 类型与 `MOTION_INTENTS` 清单（与 `docs/conventions/motion-interaction.md §3` 逐条对应），`intent-specimens.tsx` 用 `SPECIMENS` 字典把 id 映射到具体标本组件；标本实现按职责拆分为 `specimens-controls.tsx`、`specimens-overlays.tsx`、`specimens-layout.tsx`，由 `specimen-stage.tsx` 统一渲染。
- 依赖方向单向向下：页面 → registry/motion-intents → demo/specimen 组件，不反向引用业务代码，仅消费 `*.demo` 导出。
- 测试文件 `registry.test.ts`、`motion-intents.test.ts` 分别覆盖登记表与意图计数逻辑。
