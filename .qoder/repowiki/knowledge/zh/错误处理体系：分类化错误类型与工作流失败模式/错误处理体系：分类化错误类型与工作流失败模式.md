## 1. 系统/方法概述

PurpleInk 采用「自定义 Error 子类 + 统一分类器 + Next.js 错误边界」的分层错误处理体系：
- **领域错误类**：每个业务域定义专门的 `extends Error` 子类（如 `RouteContractError`、`ProviderUnavailableError`、`ArtifactValidationError`、`BillingQuotaExhaustedError`、`UnauthenticatedError`），通过 `name` 字段进行类型识别。
- **统一分类器**：`classifyWorkflowError` 将任意异常投影为统一的 `WorkflowErrorProjection`（含 `code`、`message`、`retryable`），判定顺序为「类型优先 → 文案规则 → 阶段兜底」，确保内部矛盾不会被误判为外部服务故障。
- **Next.js 错误边界**：根级 `global-error.tsx` 捕获未处理错误，`not-found.tsx` 处理 404，均只显示类别与 digest，不回显原始错误内容。
- **服务端 API 中间件**：`server/src/server/api.ts` 的 `handle` 函数统一 catch 未处理异常，通过 `errorMessage` 脱敏后返回 JSON。

## 3. 架构与约定

### 错误分类三阶段
1. **按类型判定**（`classifyByType`）：优先识别结构化错误（zod 合同、语义门禁、特定 Error 子类），避免被文案关键词误导。
2. **按文案规则**（`classifyByMessage`）：使用有序正则匹配外部原因（凭据、额度、缺失产物等），先具体后笼统。
3. **按阶段兜底**（`classifyByStage`）：根据阶段名称给出默认类别，禁止所有未识别错误都自称「渲染失败」。

### 错误投影规范
所有错误最终投影为 `WorkflowErrorProjection`：
- `code`: 18 种预定义错误码（如 `UPSTREAM_ARTIFACT_MISSING`、`PROVIDER_FAILED`、`RETRY_BUDGET_EXHAUSTED`）
- `message`: 用户可读的中文文案，不泄露 provider 原始响应、prompt、凭据或隐藏推理
- `retryable`: 布尔值，决定 UI 是否展示重试按钮、recovery 是否自动重排
- `stage` / `sourceNodeId`: 由调用上下文补齐

### 安全约束
- 对外错误文案只保留 `message`，不外泄 stack 或本机绝对路径（`error-message.ts`）
- 404 页面刻意不区分「不存在」与「无权访问」，避免泄露其他 workspace 对象是否存在
- Zod 违规只暴露字段路径（不含取值），最多列出 3 个关键路径

## 4. 约定与约束

### 已确立的约定（描述性）
- 所有领域错误必须继承 `Error` 并设置 `name` 属性，以便分类器按类型识别
- 内部应用矛盾（配置错误、合同不匹配）必须标记 `retryable=false`，防止无限重试必败作业
- 外部服务故障（网络超时、provider 不可用）标记 `retryable=true`，允许熔断窗口后重试
- 客户端认证错误统一映射为 `AuthRequestError`，不猜测原因、不区分「账号不存在」与「口令错」
- 401 响应统一抛出 `UnauthenticatedError`，由 `useRequireLogin().handleAuthError` 统一处理

### 文档化规则（来自 `workflow-failure-patterns.md`）
- **模式 B 规则**：`classifyWorkflowError` 的判定顺序是类型→文案→阶段，类型永远优先于文案
- **模式 C 规则**：以 `Record<CanvasNodeType, …>` 表达的映射改动必须配全集遍历断言
- **模式 D 规则**：读取异步媒体产物必须 `safeParse` 后给出明确的「尚未就绪」错误
- **模式 H 规则**：容灾护栏分四层（进程中断回收、自动重试+预算闸门、人为跳过、Provider 熔断降级），四者互斥
- **提交前清单**：涉及工作流链路改动必须核对 fixture 形状、重启 dev server、验证节点状态变化

### 测试覆盖要求
- `workflow-error.test.ts` 覆盖「非渲染阶段不得称渲染失败」「schema 失败必须点名字段且不可重试」
- 所有 `Record<…>` 映射必须有全集遍历断言（见模式 C 护栏）
- 真实产物证据需核对 `artifacts.content_hash` 与磁盘字节 SHA-256 一致
