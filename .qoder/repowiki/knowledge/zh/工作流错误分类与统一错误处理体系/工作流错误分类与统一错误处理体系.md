本仓库采用「领域错误类型 + 统一分类器 + 脱敏文案投影」的分层错误处理体系，覆盖 Next.js API 路由、独立渲染 Worker（server/）以及前端 UI。核心设计目标是：不泄露内部细节、准确区分可重试与不可重试错误、为不同阶段提供一致的失败语义。

## 1. 系统与方法
- **领域专用错误类**：各功能域定义具名 Error 子类，通过 error.name 被上层分类器识别，避免依赖字符串匹配。包括 ProviderUnavailableError（AI 服务熔断且无备选）、RouteContractError（模型路由配置矛盾）、ArtifactValidationError（上游产物校验失败）、QuotaExhaustedError（配额耗尽，来自 billing 模块）、UnauthenticatedError（401 会话过期，供客户端统一拦截）。
- **统一分类器**：src/features/canvas/workflow-error.ts 中的 classifyWorkflowError 是跨所有阶段的错误归一化入口，按三段顺序判定：classifyByType（基于 error.name 的结构性错误，优先级最高）、classifyByMessage（基于正则规则的文案匹配）、classifyByStage（兜底按阶段职责映射）。
- **结构化失败响应**：认证域使用 AuthFailure 对象（ok: false + code + message），而非抛错，由调用方统一转换为 HTTP 状态码。

## 2. 关键文件与位置
- src/features/canvas/workflow-error.ts — 工作流错误分类器与 19 种 WorkflowErrorCode
- src/features/auth/errors.ts — 认证失败代码、HTTP 状态映射与 authFailure() 构造器
- src/features/auth/unauthenticated-error.ts — 客户端 401 统一错误类型
- src/features/ai/provider-unavailable-error.ts / route-contract-error.ts — AI 层专用错误
- src/features/director/artifact-validation-error.ts — 产物校验失败
- src/features/billing/contracts.ts — QuotaExhaustedError 定义
- server/src/lib/error-message.ts — 对外错误消息脱敏工具
- server/src/server/api.ts — 独立 Worker 的 HTTP 错误处理
- src/app/global-error.tsx — Next.js 根级错误边界

## 3. 架构与约定
- 错误传播路径：底层抛出具名 Error → 中间层捕获并传入 classifyWorkflowError({ stage, sourceNodeId }) → 得到 WorkflowErrorProjection → API 路由返回标准化 JSON。
- 安全约束：所有对外错误只暴露 message，不泄露 stack、绝对路径、provider 原始响应、prompt 或凭据；zod 违规只显示字段路径前 3 项。
- 重试语义：retryable 字段严格区分内部矛盾一律 false、外部抖动为 true。
- 文档驱动：docs/conventions/workflow-failure-patterns.md 以模式 A~H 记录历史事故与对应护栏。

## 4. 约定与约束
- 新增错误来源必须先问外部原因还是应用内部矛盾，内部矛盾必须 retryable=false。
- classifyWorkflowError 的判定顺序不可更改：类型优先于文案。
- 认证端点不得泄露账号是否存在。
- 兜底类别必须按阶段职责分配，禁止所有未识别错误都自称渲染失败。
- 测试必须覆盖新错误的分类结果。
