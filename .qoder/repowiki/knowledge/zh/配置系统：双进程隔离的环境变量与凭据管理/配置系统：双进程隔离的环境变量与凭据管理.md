PurpleInk 采用「Next 应用进程 + 独立渲染 Worker（server/）」的双进程架构，配置系统围绕环境变量加载、凭据隔离与运行时解析三层设计展开。

## 1. 环境文件分层与加载顺序

- **Next 进程**：根目录 `.env.example` 声明 Next 侧消费的变量（数据库、托管 AI Key、邮件 SMTP、反代地址等），真实值写入被 Git 忽略的 `.env.local`。Next 构建时通过 `next.config.ts` 读取 `BACKEND_ORIGIN` 等变量，用于反向代理到后端 worker。
- **Worker 进程**：`server/.env.example` 声明 worker 专用变量（StepFun、IMAP、TTS、Gemini、SMTP 等）。启动时 `server/src/index.ts` 调用自定义 `loadEnv()` 依次加载 `server/.env` → 仓库根 `.env.local`（后者可覆盖同名键），不引入第三方依赖。
- **TTS 独立模板**：`config/tts.env.example` 单独存放 TTS provider 配置，与 root/server 的 .env 分离。

`load-env.ts` 实现极简解析：逐行读取、跳过注释和空行、去除成对引号、仅当 key 不存在时才注入 `process.env`，避免覆盖已有环境变量。

## 2. 凭据隔离与双存储路径

根据 `docs/configuration/credentials.md` 的强制约定，凭据存在两条完全隔离的路径：

| 维度 | Next 应用（Director 画布管线） | 后端 Worker（server/） |
|------|-------------------------------|------------------------|
| 进程 | `pnpm dev`, `next start` | `pnpm dev:worker`, `node server/src` |
| 密钥文件 | 根 `./.env.local` | `./server/.env` |
| 变量命名 | 托管服务使用 `CVC_MANAGED_STEPFUN_API_KEY` 等 | `GEMINI_API_KEY`, `STEP_API_KEY`, `STEP_*` |
| 运行时解析 | 三家内置托管服务只读 server-only env；自定义 OpenAI-compatible 继续使用 DB 加密凭据 | env → code default |
| Bootstrap 写入 | `scripts/setup/bootstrap-credentials.ts` 仅服务历史/自定义凭据 | 无（worker 启动时直接读 env） |

- **平台托管 Key**：Next 侧通过 `src/features/ai/managed-credentials.ts` 解析 `CVC_MANAGED_*` 变量，仅接受 StepFun、MiMo、Gemini 三家内置服务。
- **自定义 BYOK**：OpenAI-compatible 提供商继续使用 DB 加密的 `provider_credentials` 表，由 `PostgresProviderCredentialStore` 管理。
- **Bootstrap 流程**：克隆后先执行 `provision-master-key.ts` 生成主密钥，再运行 `bootstrap-credentials.ts` 验证并加密写入 DB，之后运行时不再读取 env 中的旧变量名。

## 3. 运行时配置解析与默认值

以 StepFun 为例（`src/features/ai/config.ts`）：
- 字段级优先级：`env` > `default`（代码默认值）
- baseUrl 支持从 `STEPFUN_BASE_URL` 覆盖，其他模型字段仅走默认值
- `describeStepfunConfig()` 返回 `{value, source}` 视图，不包含 apiKey，防止泄露

所有配置解析函数都标记 `'server-only'`，确保客户端无法直接访问敏感配置。

## 4. 安全约束与契约测试

- **AGENTS.md §7** 强制：secret 类变量值必须留空；真实值只写被忽略的 `.env.local`；禁止携带 secret 的 `NEXT_PUBLIC_*`。
- **tests/env.test.ts** 断言：root `.env.example` 中敏感变量名存在但值为空；Next 侧不消费 worker 专用变量（如 `STEP_API_KEY`、`LISTENHUB_API_KEY`、`IMAP_PASSWORD` 等）；Web 配置不会解析 TTS 凭据。
- **文档约束**：`docs/configuration/credentials.md` 是绑定性规范，任何变更必须先更新文档再改代码。

## 5. 部署与容器化

- `docker-compose.dev.yml` 仅定义 PostgreSQL 服务，环境变量通过 Docker 注入。
- `deploy/reverse-proxy/` 包含 Caddyfile 和 Basic Auth 凭据示例，用于生产入口认证。
- Next 构建产物通过 `next.config.ts` 的 `rewrites` 将 `/api/engine/*` 转发到 `BACKEND_ORIGIN` 指定的 worker 地址，实现同源部署、浏览器无跨域。

## 6. 设计决策总结

- **拒绝统一 env loader**：Next 与 worker 保持各自为政，避免单点故障和配置漂移。
- **拒绝 YAML/JSON 配置文件**：DB > env > default 的三级优先级已足够，无需第四层。
- **拒绝运行时 fallback**：apiKey 不允许回退到 env，由契约测试强制执行。
- **最小化依赖**：`.env` 加载自实现，不引入 dotenv 等库，减少攻击面。
