# FABRICATE 输出预算上调至 48000 字符并采用许愿式 prompt 基调

_来源：358c6a2 → 83136b7 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
Director 管线中 FABRICATE 阶段生成的 HTML 视觉质量退化，原 16000 字符预算不足以支撑高质量动效与精细还原。需在不改动重试函数签名（同会话历史已含完整上下文）的前提下提升单镜产出质量。

## 决策驱动
- Gemini maxTokens 65536 与 StepFun 32768 的 provider 能力上限
- 分镜拆细后单镜内容减少但需要更高保真度
- 避免为凑长度堆无意义代码的护栏

## 备选方案
- **上调至 48000 字符 + 许愿式 prompt** — 优点：在 provider 能力范围内最大化输出空间；通过优先视觉效果指令引导模型发挥最强能力；保留确定性红线与画幅约束
- **收紧至 8000 字符** _（已否决）_ — 优点：降低 token 成本；缺点：与明确的用户指令相反，无法支撑高质量动效
- **重构重试函数签名重注入上下文** _（已否决）_ — 优点：显式传递上下文；缺点：经核实同一 DirectorSession 内 messages 已累积，属不必要改动

## 决策
将 fabricate.ts 预算常量从 16000 上调至 48000，主 prompt 改为许愿式基调（优先保证视觉效果、充分使用 GSAP 高级特性），删除抑制性措辞但保留反膨胀护栏与确定性红线。

## 影响
单镜 HTML 输出量显著增加，需关注 API 调用成本；测试断言从 16000 个字符以内更新为 48000 个字符以内；队列并发配置暂不修改，待实测吞吐后再调优。
