## 1. 系统与架构概览

PurpleInk 采用「双进程、双环境文件」的隔离式配置体系：Next.js 应用进程与独立的 purpleink-server worker 进程各自维护独立的 .env 文件，运行时互不交叉读取。配置加载遵循「数据库 > 环境变量 > 代码默认值」的优先级顺序，AI 提供商密钥（API Key）在 Next 侧仅从 Postgres 加密表 provider_credentials 读取，绝不回退到明文环境变量。

- Next 应用进程：通过 @next/env 的 loadEnvConfig(process.cwd()) 加载根目录 .env.local，由 Next 自身在 dev/start 时自动处理。
- 后端 worker：入口 server/src/index.ts 调用自定义极简 loadEnv() 依次加载 server/.env → 仓库根 .env.local（后者可覆盖同名键），然后启动 HTTP 服务。
- TTS 配置：独立模板文件 config/tts.env.example，worker 启动时按 TTS_PROVIDER 选择具体 TTS 实现。

## 2. 关键文件与包

- .env.example：Next 进程环境变量模板（含数据库、AI 端点、SMTP 等，secret 留空）
- server/.env.example：Worker 进程环境变量模板（StepFun、IMAP、TTS、Gemini、SMTP）
- config/tts.env.example：TTS provider 专用配置模板
- server/src/lib/load-env.ts：极简 .env 解析器（无第三方依赖，支持引号包裹值，已存在键不覆盖）
- server/src/index.ts：Worker 启动入口，按序加载两个 .env 文件后起服务
- next.config.ts：Next 配置，通过 BACKEND_ORIGIN 反向代理 /api/engine/* 到 worker
- scripts/setup/bootstrap-credentials.ts：冷启动脚本：验证并加密写入 AI 提供商密钥到 DB
- docs/configuration/credentials.md：凭据系统的权威文档，定义边界与不变量

## 3. 架构与设计决策

### 3.1 双进程隔离
Next 与 worker 的环境变量命名刻意不同（STEP_API_KEY vs STEPFUN_API_KEY、GEMINI_API_KEY 同名但值独立），避免共享 loader 造成的漂移。docs/configuration/credentials.md 明确声明这是有意为之的隔离，不是需要去重的重复。

### 3.2 凭据加密存储（DB-only）
Next 侧的 apiKey 字段全部从 provider_credentials 表通过 deps.credentials.loadSecret(...) 读取，无任何 env fallback。该约束由 AGENTS.md §7、契约测试 config.test.ts:119 和 gemini-config.test.ts:93 双向锁定。Bootstrap 脚本是唯一的写入路径：先经真实 API 验证，再写入加密存储，随后清空进程中的明文 env 变量。

### 3.3 配置优先级
- Next 侧：DB 加密存储（apiKey）→ 环境变量（*_BASE_URL / *_MODEL）→ 代码默认值
- Worker 侧：环境变量 → 代码默认值
- TTS：TTS_PROVIDER 决定具体实现，其余参数按 provider 约定读取

### 3.4 安全约束
- secret 类变量（API key / master key / 口令）值必须留空于 .example 文件
- 真实值只写在被忽略的 .env.local / server/.env，禁止提交
- 禁止携带 secret 的 NEXT_PUBLIC_*
- CVC_CREDENTIAL_MASTER_KEY 缺失或格式错误时直接抛错，无明文 fallback

## 4. 约定与约束

- 环境变量命名隔离：Next 用 STEPFUN_*，worker 用 STEP_*，同名 GEMINI_API_KEY 也是独立副本
- 凭据永不回退 env：运行时 getGeminiConfig() / getStepfunConfig() 中不允许出现 process.env.GEMINI_API_KEY ?? storedKey 模式
- Bootstrap 单写路径：除 POST /api/settings 外，只有 bootstrap 脚本能写入 provider_credentials，且必须先通过真实 API 验证
- 设置页只暴露非密信息：describeGeminiConfig() / describeStepfunConfig() 返回的 value/source 对不含 apiKey
- TTS 配置独立：不在根 .env.example 中列出，由 config/tts.env.example 单独管理
- 反向代理配置：BACKEND_ORIGIN 控制 Next → worker 的转发目标，默认 http://localhost:8787
