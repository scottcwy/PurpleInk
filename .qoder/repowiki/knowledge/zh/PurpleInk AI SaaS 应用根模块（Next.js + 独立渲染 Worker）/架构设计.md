项目采用前后端分离的双进程架构：
- 前端基于 Next.js 16（App Router），`src/app` 按路由分组 `(auth)`、`(marketing)`、`(public)`、`products/(app)`，通过 `next.config.ts` 的 `rewrites` 将 `/api/engine/*` 反向代理到后端 Worker（默认 `http://localhost:8787`）。
- 后端为独立 pnpm workspace 子包 `server/`（`purpleink-server`），使用 `tsx` 运行，内部按职责划分为 `adapter`（页面采集适配器）、`capture`（Playwright/Mock 驱动）、`compose`（章节/模板/渲染管线）、`tts`（多供应商 TTS 编排）、`server`（API/Job Runner/Store）等子目录。
- 数据库层通过 Drizzle ORM 管理 PostgreSQL 模式，迁移脚本位于 `scripts/setup/db-migrate.ts`，测试使用 `vitest.pg.config.ts` 连接真实 Postgres。
- 队列消费由 Next.js `instrumentation.ts` 在 Node 运行时启动，避免构建期误启；失败时回退到 API 路由首次请求兜底初始化，防止 split-brain。
- 部署通过 Dockerfile + docker-compose（dev/prod 两套）+ Caddy 反向代理（`deploy/reverse-proxy/Caddyfile`）完成，生产环境仅暴露单域名，Worker 不对外暴露。
