- feature 目录按业务域划分（ai、auth、billing、canvas、director、render 等），每个 feature 内自包含 domain、service、repository、schemas、tests 等文件。
- API 路由遵循 Next.js App Router 约定，server 侧逻辑通过 /api/engine 反向代理转发，前端统一走同源 /api/* 路径。
- 数据库访问通过 Drizzle ORM，schema 定义集中管理，测试使用 .pg.test.ts 后缀区分需要 PostgreSQL 的集成测试。
- 环境变量通过 .env.example 模板 + process.env 读取，敏感配置通过 deploy/reverse-proxy/secrets 目录管理。
- 组件命名采用 PascalCase，UI 组件放在 src/components/ui 并提供 .demo.tsx 与可选 .test.tsx 配套文件。
- 错误处理通过自定义 error classes（如 provider-unavailable-error.ts、unauthenticated-error.ts）并配合 Zod schema 进行输入校验。
