## 1. 采用的系统与模式
- **领域级自定义 Error 类**：在 `src/features/director/artifact-validation-error.ts` 定义 `ArtifactValidationError`，在 `src/features/ai/route-contract-error.ts` 定义 `RouteContractError`，通过 `name` 字段进行类型识别。
- **结构化失败返回（Auth）**：`src/features/auth/errors.ts` 用 `AuthFailureCode` + `authFailure()` 工厂函数返回 `{ ok: false, code, detail?, retryAfterMs? }` 的 discriminated union，配合 `isAuthFailure` 守卫，避免泄露账号是否存在。
- **工作流错误分类器**：`src/features/canvas/workflow-error.ts` 的 `classifyWorkflowError(error, context)` 将任意异常投影为 `WorkflowErrorProjection { code, stage, message, retryable, sourceNodeId? }`，按「类型优先 → 文案规则 → 阶段兜底」三段判定，屏蔽 provider 原始响应与凭据。
- **服务端统一脱敏**：`server/src/lib/error-message.ts` 的 `errorMessage(err)` 只取 `message`，不暴露 stack / 绝对路径；`tests/worker-error-hygiene.test.ts` 以契约测试强制所有对外 error 字段走该函数。
- **Next.js 错误边界**：`src/app/global-error.tsx` 作为根级兜底，仅展示 digest 与重试按钮；`src/app/not-found.tsx` 提供统一的 404 页面，刻意不区分「不存在」与「无权访问」。

## 2. 关键文件与包
- `src/features/auth/errors.ts` — 认证域失败码、状态映射与消息集中管理
- `src/features/canvas/workflow-error.ts` — 工作流错误分类与可重试性判定
- `src/features/director/artifact-validation-error.ts` — 产物校验失败的专用 Error
- `src/features/ai/route-contract-error.ts` — 路由/能力合同矛盾的专用 Error
- `server/src/lib/error-message.ts` — 对外错误文案脱敏工具
- `server/src/server/job-runner.ts` — Job 执行器，错误写入任务表时仅保留 message
- `server/src/server/api.ts` — HTTP API 全局 catch，500 响应体使用 `errorMessage`
- `src/app/global-error.tsx` / `src/app/not-found.tsx` — Next.js 根级错误与 404 边界
- `tests/worker-error-hygiene.test.ts` — 强制“不向外泄漏栈/内部路径”的契约测试

## 3. 架构与约定
- **错误分层**：领域层抛出自定义 Error（`ArtifactValidationError`、`RouteContractError`），canvas 层将其归类为业务错误码（`UPSTREAM_ARTIFACT_INVALID`、`ROUTE_CONTRACT_INVALID` 等），UI 层只消费 `WorkflowErrorProjection` 的 `code/message/retryable`。
- **安全约束**：认证端点统一 401/429/503 等状态码，验证码接口对已注册/未注册邮箱返回相同 200 与同一句文案，防止枚举攻击。
- **可观测性分离**：完整 stack 仅进入 `logger.error`，对外 JSON 响应只含 `errorMessage(err)`，由契约测试保证不被绕过。
- **可重试性声明**：分类器为每个错误码标注 `retryable`，上层据此决定是否提示用户重试或引导修复上游。

## 4. 约定与约束
- 认证失败必须使用 `AUTH_FAILURE_STATUS` 与 `AUTH_FAILURE_MESSAGE` 中的固定映射，不得自行拼接差异化文案（`src/features/auth/errors.ts` 注释明确禁止泄露账号存在性）。
- 工作流错误必须经 `classifyWorkflowError` 分类，禁止直接透传 provider 原始错误到 UI（分类器注释强调“不回显 provider 原始响应、prompt、凭据或隐藏推理”）。
- 所有对外暴露的错误字段必须经过 `errorMessage` 脱敏，`tests/worker-error-hygiene.test.ts` 通过源码匹配断言禁止直接使用 `String(err?.stack)` 或 `String(err)` 写入公开错误字段。
- Next.js 根级错误边界 `global-error.tsx` 不依赖 Providers/字体/主题脚本，确保在最坏情况下仍可渲染；404 页面刻意模糊「不存在」与「无权访问」差异（遵循 `docs/conventions/routing.md §9.2`）。
- 自定义 Error 类必须设置唯一的 `name`（如 `ArtifactValidationError`、`RouteContractError`），以便分类器在文案匹配前按类型优先判定。
