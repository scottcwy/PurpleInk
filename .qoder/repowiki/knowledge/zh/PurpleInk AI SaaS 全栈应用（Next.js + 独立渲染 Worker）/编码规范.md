- 每个业务功能以 src/features/<domain>/ 为边界组织，按能力拆分为多个文件（如 ai/ 下按 provider、config、store、adapter 等细分），测试文件与源码同名并列放置（*.test.ts）。
- 组件与工具函数采用「实现文件 + .demo.tsx + .test.ts」三件套模式，便于 Storybook 式预览与单元测试同步维护。
- 环境变量通过 zod schema 校验后注入，配置文件集中在 features/*/config.ts 或 lib/config/ 中，运行时通过 load-env.ts 统一加载。
- 错误处理统一封装在 lib/error-message.ts 与 features/*/provider-request-error.ts 等文件中，区分用户可见错误与内部诊断信息。
- API Route 与内部 API 分离：公开 API 放在 src/app/api/*，内部服务间通信通过 server/src/server/internal-api.ts 与 internal-auth.ts 保护。
- 所有异步任务通过 server/src/server/job-runner.ts 与 job-store.ts 统一管理，job 状态持久化并支持重试与降级。
