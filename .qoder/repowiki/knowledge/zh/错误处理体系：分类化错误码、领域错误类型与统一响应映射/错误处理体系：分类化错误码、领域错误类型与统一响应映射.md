本仓库采用「领域错误类型 + 工作流错误分类器 + 统一响应映射」的分层错误处理体系，覆盖认证、AI 模型路由、导演流水线、渲染与 TTS 等核心链路。

### 1. 系统与方法
- **领域错误类**：每个业务域定义专属 `Error` 子类，通过 `name` 字段被上层分类器识别，避免依赖文案匹配。
- **工作流错误分类器**：`src/features/canvas/workflow-error.ts` 的 `classifyWorkflowError` 以「类型优先 → 文案规则 → 阶段兜底」三段式将任意异常投影为 `WorkflowErrorProjection`（含 `code`、`message`、`retryable`），确保 UI 只展示脱敏后的业务类别。
- **认证失败枚举**：`src/features/auth/errors.ts` 用 `AuthFailureCode` 字符串联合 + `AUTH_FAILURE_STATUS` / `AUTH_FAILURE_MESSAGE` 映射表集中管理状态码与用户文案，禁止泄露账号是否存在。
- **统一响应映射**：`src/features/auth/http.ts` 的 `authFailureResponse` 把 `AuthFailure` 转为 `{ ok: false, error: 文案 }` 的 JSON，并附带 `Retry-After` 头；服务端通用脱敏函数 `server/src/lib/error-message.ts` 仅提取 `err.message`，不暴露 stack 或绝对路径。

### 2. 关键文件与包
- `src/features/canvas/workflow-error.ts` — 工作流错误分类器与 `WorkflowErrorCode` 全集
- `src/features/ai/provider-unavailable-error.ts` — Provider 熔断不可用错误
- `src/features/ai/route-contract-error.ts` — 路由/能力合同矛盾错误
- `src/features/director/artifact-validation-error.ts` — 产物校验失败错误
- `src/features/auth/errors.ts` — 认证失败代码、状态码与文案映射
- `src/features/auth/unauthenticated-error.ts` — 客户端可识别的未登录错误
- `src/app/global-error.tsx` — Next.js 根级错误边界（digest 参考号）
- `src/app/not-found.tsx` — 404 页面（不区分不存在与无权访问）
- `server/src/lib/error-message.ts` — 对外错误文案脱敏工具
- `docs/conventions/workflow-failure-patterns.md` — 工作流失败模式手册（事故复盘与护栏规范）

### 3. 架构与约定
- **错误分类顺序严格固定**：`classifyByType`（zod 合同、领域错误类名）→ `classifyByMessage`（正则规则，按具体到笼统排序）→ `classifyByStage`（按阶段职责兜底）。类型判定永远优先于文案，防止 zod 报文中的 `required`/`invalid` 等词误命中外部服务规则。
- **retryable 语义由错误来源决定**：内部矛盾（合同不一致、凭据缺失）标记 `retryable=false`，外部抖动（网络超时、provider 5xx）标记 `retryable=true`。分类器对 `RETRY_BUDGET_EXHAUSTED`、`PROVIDER_FAILED`、`TASK_INTERRUPTED` 等场景给出固定投影。
- **四段容灾护栏**（文档模式 H）：进程中断自动回收 → 自动重试+预算闸门 → 人为跳过（仅限可降级节点）→ Provider 熔断+显式备选降级。四层互斥，不得混用同一错误码。
- **安全约束**：所有对外错误只返回 `message`，不回显 provider 原始响应、prompt、凭据、字段取值或堆栈；404 页面不区分「不存在」与「无权访问」，避免 workspace 对象存在性枚举。
- **Next.js 错误边界**：`global-error.tsx` 作为根级兜底，独立 html/body，不依赖 Providers；`not-found.tsx` 承载未匹配路由与 `notFound()` 传播。

### 4. 约定与约束
- 新增错误来源必须先问「外部原因还是应用内部矛盾」，内部矛盾必须 `retryable=false`，否则 UI 会展示无效的重试按钮。
- 跨阶段数据结构只能有一个 zod 定义（SSOT），不得内联重写上游契约的子结构。
- 异步媒体产物读取必须走 `safeParse` 并返回 `MEDIA_NOT_READY`，不得把文本产物丢给音频 schema 硬解析。
- 任何 `Record<CanvasNodeType, …>` / `Record<PipelineStage, …>` 映射改动必须配全集遍历断言，防止漏掉正在使用的节点类型。
- fixture 必须使用真实产物形状，最小对象仅用于反向断言。
- 改动 queue handler、stage runner、模型路由后必须重启 dev server 再验证，以真实节点状态变化为证据。
- artifact 指向的文件必须在生产者关闭后计算哈希，不得提前登记可追加文件。
- 跳过语义仅限用户显式请求进入，自动链路永远不得自行跳过节点。
- Provider 熔断记账单一收敛点在 `pi-session.ts` 的 run 结果处，内部矛盾（如 `RouteContractError`）不得污染计数。
