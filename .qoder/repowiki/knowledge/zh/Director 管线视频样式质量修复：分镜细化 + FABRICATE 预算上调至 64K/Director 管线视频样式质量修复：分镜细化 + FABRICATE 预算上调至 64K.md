# Director 管线视频样式质量修复：分镜细化 + FABRICATE 预算上调至 64K

_来源：21c9b6a → 1b6c0a3 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
Director 管线生成的视频样式出现退化，视觉表现力不足。根因是 FABRICATE 阶段输出预算仅 16000 字符（远低于模型 64K 上限），且分镜粒度粗糙导致单镜头承载过多内容。

## 决策驱动
- 最大化利用模型输出能力
- 提高分镜精度以增强视觉表现力
- 保持语义完整性
- 避免不必要的架构改动

## 备选方案
- **FABRICATE 预算上调至 64000 字符 + 许愿式 prompt** — 优点：充分利用模型 64K 输出上限，提升视觉保真度；通过高质量指令引导最佳设计决策
- **styleBible 结构化 JSON schema** _（已否决）_ — 优点：更严格的契约约束；缺点：需要改 DIRECT 输出契约、解析器与全部下游注入点，风险大；当前退化主因是预算与粒度而非结构问题
- **重试函数签名改造重注入完整上下文** _（已否决）_ — 优点：显式保证重试时上下文完整；缺点：经核实同会话历史已含完整上下文，属不必要改动
- **显式 cache control API 接入** _（已否决）_ — 优点：可控的缓存策略；缺点：pi-provider/billing 层改造面大；隐式前缀缓存已能覆盖主要收益

## 决策
将 FABRICATE 预算从 16000 上调至 64000 字符，采用许愿式 prompt 基调（优先视觉效果、使用 GSAP 高级特性）；在 INGEST 阶段按 1-2 句话一镜的粒度拆分 script units；通过 prompt 分层排布实现隐式缓存友好；重试时追加质量保持指令但不改函数签名。

## 影响
单项目镜头数增至 2-3 倍，现有队列并发配置需后续按实测吞吐调整；降级到 StepFun（maxTokens 32768）时输出能力低于预算，通过降级标记保证可观测性；不引入显式缓存 API，依赖 provider 隐式前缀缓存。
