本仓库的日志系统由 server/ 子工程内的一个极简 logger 模块提供，采用「事件名 + 结构化 data」的统一格式，通过 console.log / console.warn / console.error 输出到标准流，由容器或进程管理器收集。

**框架与实现**
- 核心定义位于 `server/src/lib/logger.ts`，仅导出 `logger.info`、`logger.warn`、`logger.error` 三个方法，签名统一为 `(event: string, data?: Record<string, unknown>) => void`。
- 输出格式为 `[LEVEL] event message`，data 参数以 `JSON.stringify(data)` 追加在消息末尾，便于外部解析。
- 该模块是直接从 Firenze frameproof 项目拷贝而来（文件内注释明确标注），未引入任何第三方日志库，保持零依赖。

**使用范围与调用方**
- 所有 server/ 子工程的业务模块均通过相对路径导入 `../lib/logger`，包括：
  - HTTP API 层 (`server/src/server/api.ts`)：记录请求入队、视频流失败、服务监听端口等。
  - Job 执行器 (`server/src/server/job-runner.ts`)：记录任务完成与失败，错误时附带完整 stack。
  - 采集 Agent (`server/src/capture/ai-capture-agent.ts`)：记录截图、认证、AI 决策、循环检测等流水线关键节点。
  - StepFun 客户端 (`server/src/lib/step-client.ts`)：记录网络重试、限速退避等异常路径。
  - 渲染管线、LLM 响应解析、适配器等多个子模块。
- Next.js 前端 (`src/`) 未使用该 logger，生产构建通过 `next.config.ts` 的 `compiler.removeConsole.exclude` 配置保留 `console.error` 和 `console.warn`，确保 Node 端错误能落到容器日志。

**日志级别策略**
- `info`：正常业务流程的关键事件（job 完成、API 入队、采集步骤推进）。
- `warn`：可恢复异常或降级路径（网络重试、AI 决策失败、截图失败）。
- `error`：不可恢复错误（job 失败、HTTP 500、视频流读取失败），并附带完整堆栈。
- 没有 debug 级别；调试信息直接通过 console.log 输出，在生产构建中被移除。

**结构化字段约定**
- 每个事件名遵循 `<模块>:<动作>` 命名模式（如 `api:render_queued`、`ai_capture:step`、`job:done`、`step_client:retry`）。
- data 对象包含上下文关键字段：`id`（job/capture id）、`step`（当前步骤）、`url`、`error`、`attempt`、`status`、`stack` 等，便于按事件类型查询。
- 错误信息经过 `errorMessage()` 工具函数处理后再写入，避免向用户暴露敏感路径。

**约束与限制**
- 无日志级别过滤、无异步写入、无采样、无集中式聚合；完全依赖运行环境的 stdout/stderr 收集。
- 生产环境 `console.log` 被 Next.js 编译器移除，但 `console.error` 和 `console.warn` 通过 `exclude` 配置保留，确保错误路径仍有诊断信息。
- 未实现日志轮转、持久化或远程上报，适合单容器部署场景。
