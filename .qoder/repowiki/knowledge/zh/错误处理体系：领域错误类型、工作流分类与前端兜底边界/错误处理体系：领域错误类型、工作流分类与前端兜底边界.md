## 1. 系统/方法概述
该仓库采用「领域错误类型 + 工作流错误分类 + 前端全局错误边界」的分层策略：
- 领域层定义专用 Error 子类（如认证、AI Provider、产物校验等），通过 name 属性进行精确识别。
- 工作流层提供统一的 classifyWorkflowError，按「类型优先 → 文案规则 → 阶段兜底」三段式将任意异常投影为可展示、可判定是否重试的 WorkflowErrorProjection。
- 前端 Next.js 使用 global-error.tsx 作为根级错误边界，统一呈现未处理错误并隐藏原始堆栈。
- 服务端对外错误文案通过 errorMessage 剥离 stack/路径等敏感信息，仅保留 message。

## 2. 关键文件与包
- server/src/lib/error-message.ts：对外错误文案提取器，只返回 err.message。
- src/app/global-error.tsx：Next.js 根级错误边界，显示 digest 参考号并提供重试按钮。
- src/app/not-found.tsx：404 页面，刻意不区分「不存在」与「无权访问」避免泄露信息。
- src/features/auth/errors.ts：认证失败码、HTTP 状态映射与消息集中管理，遵循「不泄露账号是否存在」原则。
- src/features/auth/unauthenticated-error.ts：客户端可识别的 401 错误类型及 throwIfUnauthenticated 拦截器。
- src/features/ai/provider-unavailable-error.ts：主备 provider 均不可用时的专用错误类型。
- src/features/ai/route-contract-error.ts：路由/能力合同矛盾的错误类型。
- src/features/director/artifact-validation-error.ts：产物校验失败的错误类型。
- src/features/canvas/workflow-error.ts：核心工作流错误分类器，包含类型判定、文案规则与阶段兜底。
- server/src/lib/logger.ts：简易结构化日志记录器（info/warn/error）。

## 3. 架构与约定
- 错误类型命名规范：所有领域错误类继承 Error 并设置固定 name 属性（如 UnauthenticatedError、ProviderUnavailableError、RouteContractError、ArtifactValidationError），供 classifyWorkflowError 按类型快速匹配。
- 工作流错误分类顺序严格规定：先按 error.name 做结构性判断（ZodError、DirectorPreflightError、RouteContractError、ProviderUnavailableError 等），再按 MESSAGE_RULES 正则匹配文案，最后按 stage 回退到默认类别。此顺序确保外部服务抖动不会被误判为配置问题。
- 错误投影结构：classifyWorkflowError 输出 WorkflowErrorProjection，包含 code、message、retryable 三字段，stage 与 sourceNodeId 由调用上下文补齐，referenceId 与 occurredAt 用于追踪。
- 安全约束：errorMessage 仅暴露 message；global-error.tsx 不打印堆栈；not-found.tsx 不区分权限不足与资源不存在；AUTH_FAILURE_MESSAGE 统一登录失败文案防止枚举攻击。
- 重试语义：retryable 字段明确标识是否值得重试，ProviderUnavailableError 标记为可重试（熔断窗口后有意义），RouteContractError 标记为不可重试（修复配置前重试无意义）。

## 4. 约定与约束
- 认证域错误必须通过 AUTH_FAILURE_CODE 映射 HTTP 状态，禁止在路由中硬编码状态码。
- 客户端 API 模块收到 401 响应时必须通过 throwIfUnauthenticated 转换为 UnauthenticatedError，由 useRequireLogin().handleAuthError 统一处理弹窗登录。
- 工作流错误分类器 classifyWorkflowError 是唯一的错误归口，各阶段不得自行决定用户可见文案。
- 所有对外错误消息不得包含凭据、模型名、provider 原始响应或内部推理细节。
- 服务器端 logger.error 仅用于调试，生产环境错误详情需经 errorMessage 过滤后再返回客户端。
- 前端错误边界 global-error.tsx 不依赖 Providers 和主题初始化，确保 root layout 失效时仍可渲染。
- 404 页面不区分「无权访问」与「资源不存在」，遵循 docs/conventions/routing.md §9.2 的安全约定。

## 5. 工具与辅助
- isAuthFailure / isUnauthenticatedError / isWorkflowFault 等类型守卫函数用于运行时类型检查。
- embeddedWorkflowFault 机制允许错误对象携带已分类的 fault 投影，避免重复分类。
- describeIssuePaths 从 ZodError 中提取违规字段路径，限制最多 3 个键名且不暴露取值。

该体系通过明确的错误类型、严格的分类顺序和安全的信息披露策略，实现了从底层异常到用户可见提示的完整链路控制。
