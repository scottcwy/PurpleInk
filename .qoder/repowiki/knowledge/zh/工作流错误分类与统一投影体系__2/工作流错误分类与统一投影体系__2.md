本仓库采用「类型优先 + 文案规则 + 阶段兜底」的三层错误分类机制，配合领域专用错误类型与统一的 WorkflowFault 投影，实现跨 Next.js 前端、API 路由、渲染 worker 与工作流编排的一致性错误处理。

## 1. 系统与方法
- **分层错误类型**：各业务域定义专属 Error 子类，避免普通 `Error` 被误判为外部服务故障。
- **统一分类器**：`classifyWorkflowError` 是工作流链路上的唯一入口，按 `classifyByType → classifyByMessage → classifyByStage` 顺序判定，确保 zod 合同错误、内部矛盾与外部故障不混淆。
- **安全投影**：所有错误最终投影为 `WorkflowErrorProjection`（含 code、message、retryable、referenceId、occurredAt），原始响应、prompt、凭据不得持久化或回显。
- **Next.js 边界**：`global-error.tsx` 作为根级错误边界，`not-found.tsx` 处理 404；客户端通过 `UnauthenticatedError` 统一处理 401 会话过期。

## 2. 核心文件与包
- `src/features/canvas/workflow-error.ts`：工作流错误分类主逻辑，包含三类判定规则与阶段兜底映射。
- `src/features/ai/provider-request-error.ts`：出网边界的 Provider 异常封装，自动推断失败类型（auth/balance/rate_limit/safety/timeout/unavailable/network）。
- `src/features/ai/provider-unavailable-error.ts`：主备 provider 均不可用时的熔断错误，强制归类为 `PROVIDER_FAILED` 且可重试。
- `src/features/ai/route-contract-error.ts`：路由/能力矛盾错误，强制归类为 `ROUTE_CONTRACT_INVALID` 且不可重试。
- `src/features/auth/errors.ts`：认证失败码与状态码映射，遵循「不泄露账号是否存在」原则。
- `src/features/auth/unauthenticated-error.ts`：客户端可识别的未登录错误，由 `useRequireLogin().handleAuthError` 统一处理。
- `src/app/global-error.tsx` / `src/app/not-found.tsx`：Next.js 全局错误边界与 404 页面。
- `docs/conventions/workflow-failure-patterns.md`：工作流失败模式手册，记录已发生事故的根因、规则与护栏。

## 3. 架构与约定
- **错误分类三阶段**：
  1. `classifyByType`：基于 error.name 精确匹配（ZodError、RouteContractError、ProviderUnavailableError 等），优先级最高。
  2. `classifyByMessage`：正则规则匹配（如 quota_exhausted、HTTP 402、缺少/不存在、provider/模型/网络等关键词）。
  3. `classifyByStage`：按 stage 名称兜底（QUEUE/FABRICATE/RENDER/MEDIA_NARRATION），禁止所有未识别错误都自称渲染失败。
- **安全元数据**：每个错误生成唯一 referenceId 与 occurredAt，原始异常仅保留在内存中的 cause，不得序列化进 task_attempts.failure。
- **重试语义**：`retryable` 字段严格区分可重试（外部抖动、进程中断）与不可重试（配置错误、预算耗尽、路由矛盾），避免用户陷入无限重试循环。
- **领域隔离**：canvas 层只依赖 error.name 字符串进行类型判定，避免反向依赖 director/audio/render 等上游模块造成循环导入。

## 4. 约定与约束
- **认证安全**：登录失败与验证码请求必须返回相同文案与状态码，防止账号枚举攻击（AUTH_FAILURE_STATUS 映射 401/422/429/503）。
- **Provider 错误脱敏**：ProviderRequestError 的 message 由 safeProviderMessage 生成，不包含响应正文、Prompt、凭据或工具参数。
- **工作流失败模式**：所有新增错误路径必须对照 docs/conventions/workflow-failure-patterns.md 检查是否命中已知模式（A-N），特别是「内部错误被贴上外部标签」（模式 B）与「节点类型 × 阶段矩阵覆盖不全」（模式 C）。
- **测试门禁**：workflow-error.test.ts 覆盖「非渲染阶段不得称渲染失败」「schema 失败必须点名字段且不可重试」「各阶段兜底归位」等断言。
- **客户端统一处理**：所有 401 响应通过 throwIfUnauthenticated 转换为 UnauthenticatedError，由单一 handleAuthError 打开登录弹窗，禁止各模块各自 alert/跳转。
- **日志与审计**：日志只记录 referenceId、provider、model、status、stage、attemptId、duration 与 retryAt，禁止输出敏感信息。
