## 系统概览

PurpleInk 采用「Next.js 前端 + 独立 Node/TypeScript 渲染 Worker」的双进程架构，配置系统围绕两个相互隔离的环境文件体系构建，通过 .env 模板、运行时加载顺序和严格的命名约定实现分层管理。

## 核心架构与加载机制

### 1. 双进程环境文件隔离
- Next 应用进程：读取根目录 ./.env.local（git 忽略），由 @next/env 的 loadEnvConfig() 自动加载
- 后端 Worker 进程：通过自定义 server/src/lib/load-env.ts 手动加载，按优先级依次读取 server/.env → 仓库根 .env.local（后者可覆盖同名键）
- TTS 专用配置：config/tts.env.example 单独管理 TTS provider 参数，与主配置解耦

### 2. 环境变量加载策略
server/src/index.ts 启动流程中，先加载 server/.env，再加载根 .env.local 进行覆盖。自定义 loadEnv() 函数实现极简解析：跳过注释行、支持引号包裹值、已存在的 process.env 键不被覆盖。

### 3. Next.js 构建期配置
next.config.ts 通过 process.env.CVC_NEXT_DIST_DIR 控制构建输出目录，生产环境通过 NODE_ENV === production 启用 console 过滤（仅保留 error/warn），反向代理规则基于 BACKEND_ORIGIN 环境变量动态配置 /api/engine/* 重写。

## 配置分层与命名约定

### 平台托管凭据（Next 侧）
使用 CVC_MANAGED_* 前缀区分内置服务：CVC_MANAGED_STEPFUN_API_KEY、CVC_MANAGED_MIMO_API_KEY、CVC_MANAGED_GEMINI_API_KEY。这些变量仅被 server-only 代码读取，不会下发到浏览器或写入数据库。

### 历史/自定义凭据（DB 加密存储）
旧版 GEMINI_API_KEY、STEP_API_KEY 等仍支持但不再作为内置服务主路径，通过 scripts/setup/bootstrap-credentials.ts 验证后加密存储到 provider_credentials 表。

### 安全约束（AGENTS.md §7 强制）
secret 类变量值必须留空，真实值只写在被忽略的 .env.local/server.env；禁止提交包含 secret 的文件；禁止携带 secret 的 NEXT_PUBLIC_* 变量；CVC_CREDENTIAL_MASTER_KEY 缺失即抛错，无明文 fallback。

## 配置来源优先级

| 配置类型 | 最高优先级 | 次级优先级 | 默认值 |
|---------|-----------|-----------|--------|
| 平台托管 Key | CVC_MANAGED_* 环境变量 | 无 | 硬编码默认 |
| 自定义 BYOK | DB 加密凭据 (provider_credentials) | 环境变量 | 硬编码默认 |
| Worker 配置 | server/.env | 根 .env.local | 代码默认 |
| Next 配置 | 根 .env.local | 代码默认 | 硬编码默认 |

## 关键文件与职责

- .env.example：Next 进程环境变量模板，含数据库连接、托管 Key、邮件 SMTP 等
- server/.env.example：Worker 进程环境变量模板，含 StepFun、IMAP、TTS、Gemini 等
- config/tts.env.example：TTS provider 专用配置模板
- docs/configuration/credentials.md：凭据管理的权威文档，定义边界和约束
- server/src/lib/load-env.ts：Worker 进程的环境变量加载器
- next.config.ts：Next.js 构建期配置，处理环境变量相关的构建选项
- src/lib/api.ts：前端 API 客户端，通过 NEXT_PUBLIC_API_BASE 配置后端地址

## 部署与运维

开发环境通过 docker-compose.dev.yml 注入环境变量，本地 .env.local 覆盖默认值。生产环境容器编排通过环境变量注入，反代层（Caddy）通过 Basic Auth 保护入口。取证脚本通过 CVC_VERIFY_BASIC_AUTH 和 CVC_VERIFY_ACCOUNT 用于自动化测试认证。体验账号通过 CVC_DEMO_ACCOUNT_* 变量用于容器化建号脚本。

## 约束与最佳实践

1. 禁止统一 env 加载器：前后端保持隔离，避免配置漂移
2. 禁止 YAML 配置文件：通过 DB > env > default 的三层结构替代
3. 禁止运行时 apiKey 回退：严格遵循 AGENTS.md §7 的安全约束
4. 示例文件只列空变量名：不得包含任何真实密钥
5. 测试验证：tests/env.test.ts 强制检查前后端环境变量分离
