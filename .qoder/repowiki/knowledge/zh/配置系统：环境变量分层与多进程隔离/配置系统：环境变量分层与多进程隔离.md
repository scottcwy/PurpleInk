## 系统概述

PurpleInk 采用**基于环境变量的轻量级配置系统**，按 Next.js 前端应用与独立渲染 Worker（server/）两个进程严格隔离，通过 `.env` 文件、Docker Compose 环境变量注入以及运行时 `process.env` 读取实现配置加载。没有引入第三方配置库（如 dotenv），后端使用自实现的极简加载器。

## 核心架构与约定

### 1. 双进程配置隔离
- **Next.js 前端**：根目录 `.env.example` / `.env.local`，由 Next.js 自动加载
- **Worker 后端**：`server/.env.example` / `server/.env`，启动时手动加载
- 两者互不交叉，各自为政，遵循 AGENTS.md §7 安全约束

### 2. 配置加载优先级
Worker 启动顺序（`server/src/index.ts`）：
1. 加载 `server/.env`
2. 覆盖加载仓库根 `.env.local`（后者可覆盖同名键）
3. 读取 `process.env.PORT` 或默认 8787

### 3. 环境变量分类
- **数据库凭据**：`DATABASE_URL` / `TEST_DATABASE_URL`（Next/worker 共用）
- **凭据加密主密钥**：`CVC_CREDENTIAL_MASTER_KEY`（32字节 base64，缺失即抛错）
- **平台托管 AI 凭据**：`CVC_MANAGED_STEPFUN_API_KEY` / `CVC_MANAGED_MIMO_API_KEY` / `CVC_MANAGED_GEMINI_API_KEY`（仅 server-only 运行时）
- **AI 服务端点**：各 provider 的 `*_BASE_URL`、`*_MODEL` 变量
- **前端反代**：`BACKEND_ORIGIN`（默认 http://localhost:8787）、`NEXT_PUBLIC_API_BASE`
- **邮件通道**：`CVC_MAIL_SMTP_*`（Next 侧发验证码）
- **TTS 配置**：`config/tts.env.example` 单独管理

### 4. 运行时配置解析
- **Next.config.ts**：直接读取 `process.env.BACKEND_ORIGIN` 配置 rewrites
- **src/lib/api.ts**：`NEXT_PUBLIC_API_BASE` 控制浏览器直连路径
- **src/features/ai/config.ts**：StepFun 配置从 env → default 两级回退
- **server/src/lib/load-env.ts**：自定义 .env 解析器，支持注释和引号处理

### 5. Docker 编排配置
- **docker-compose.prod.yml**：所有生产环境变量通过 `${VAR:-default}` 语法注入
- **关键强制变量**：`POSTGRES_PASSWORD`、`CVC_CREDENTIAL_MASTER_KEY`、`CVC_REDEMPTION_CODE_PEPPER` 等必须设置
- **健康检查**：next 服务 `/api/ping`，worker 服务 `/health`
- **单实例限制**：next 固定 replicas=1（stream-bus/status-bus 是进程内状态）

### 6. 安全约束
- secret 类变量值必须留空，真实值只写被忽略的 `.env.local` / `server/.env`
- 禁止携带 secret 的 `NEXT_PUBLIC_*` 变量下发到浏览器
- 凭据通过 `CVC_CREDENTIAL_MASTER_KEY` 加密存储，不在日志或错误中暴露
- 生产环境通过 Caddy 反向代理 + Basic Auth + IP 过滤访问

## 关键文件
- `.env.example`：Next 进程环境变量模板
- `server/.env.example`：Worker 进程环境变量模板
- `config/tts.env.example`：TTS 专用配置模板
- `server/src/lib/load-env.ts`：自定义 .env 加载器
- `server/src/index.ts`：Worker 启动入口，配置加载顺序定义处
- `next.config.ts`：Next 构建期配置，直接消费环境变量
- `docker-compose.prod.yml`：生产环境完整配置注入
- `src/features/ai/config.ts`：AI 提供商配置解析逻辑

## 设计决策
- 选择环境变量而非配置文件，便于容器化部署和环境隔离
- 前后端配置分离，避免敏感信息泄露到客户端
- 使用默认值 + 环境变量覆盖的模式，提供开箱即用体验
- 通过 Docker secrets 管理最敏感的配置（如 Basic Auth 凭据）
- 迁移脚本和初始化任务通过独立的 compose service 执行，保证幂等性
