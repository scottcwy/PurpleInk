本仓库采用「领域错误类型 + 统一分类器 + 安全文案过滤」的分层策略，将内部异常投影为可展示、可重试判定的业务错误，并在所有对外出口剥离堆栈与敏感路径。核心由三部分构成：

1. 领域错误类型（features/*）
- `src/features/ai/provider-unavailable-error.ts`：ProviderUnavailableError，表示主备 provider 均不可用，强制归类为 PROVIDER_FAILED 且 retryable=true。
- `src/features/ai/route-contract-error.ts`：RouteContractError，表示路由/能力合同矛盾，强制归类为 ROUTE_CONTRACT_INVALID 且 retryable=false。
- `src/features/billing/contracts.ts`：QuotaExhaustedError / BillingIdempotencyConflictError，额度耗尽与幂等冲突语义。
- `src/features/auth/errors.ts`：AuthFailureCode 枚举 + AUTH_FAILURE_STATUS/MESSAGE 映射，集中认证失败状态码与中文文案，避免账号存在性泄露。
- `src/features/auth/unauthenticated-error.ts`：UnauthenticatedError 用于客户端统一处理 401 会话过期。
- `src/features/director/artifact-validation-error.ts`：ArtifactValidationError，上游产物校验失败。
- `src/app/products/(app)/canvas/[projectId]/canvas-action-api.ts`：BillingQuotaExhaustedError 等页面级错误。

2. 统一分类器（features/canvas/workflow-error.ts）
- `classifyWorkflowError(error, { stage, sourceNodeId })` 把任意 Error 投影为 WorkflowErrorProjection（code/message/retryable/stage/sourceNodeId）。
- 判定三段式且类型优先于文案：先按 error.name 匹配结构化错误（ZodError、QuotaExhaustedError、ArtifactValidationError、RouteContractError、RetryBudgetExhaustedError、ProviderUnavailableError），再按 MESSAGE_RULES 正则匹配外部原因，最后按 STAGE_FALLBACKS 阶段兜底。
- 严格禁止回显 provider 原始响应、prompt、凭据或隐藏推理；Zod 违规只暴露字段路径而不暴露取值。

3. 对外安全输出（server + Next.js API）
- `server/src/lib/error-message.ts`：errorMessage(err) 仅返回 err.message，丢弃 stack/绝对路径，配套 tests/worker-error-hygiene.test.ts 通过源码断言保证不泄漏。
- `server/src/server/job-runner.ts`：job 失败时 error 字段走 errorMessage(err)，完整堆栈仅进 logger.error("job:failed")。
- Next.js API 路由（如 src/app/api/render/route.ts、src/app/api/director/pipeline/route.ts）统一调用 classifyWorkflowError 生成标准化错误投影后返回。
- `src/app/global-error.tsx`：根级错误边界，只显示 digest 与通用提示，不回显原始错误内容。

架构约定
- 所有跨进程/跨模块的异常必须经过 classifyWorkflowError 投影后再序列化到数据库或 HTTP 响应。
- 对外错误文案集中在各 features 的错误定义文件中，禁止在路由层拼接用户输入或 provider 原始报文。
- 重试语义由 projection.retryable 决定，前端据此决定是否显示“稍后重试”按钮。
- 日志与对外输出分离：logger.error 保留完整堆栈，errorMessage 负责脱敏。
