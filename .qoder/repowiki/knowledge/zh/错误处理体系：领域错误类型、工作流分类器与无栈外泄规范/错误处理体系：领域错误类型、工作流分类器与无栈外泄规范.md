## 系统概述

PurpleInk 采用「领域错误类型 + 工作流错误分类器 + 统一消息脱敏」三层架构，将业务失败语义与底层异常解耦，确保对外响应不泄露内部细节（stack、路径、凭据），同时为前端提供可重试/不可重试的明确信号。

## 核心组件

### 1. 领域错误类型（Domain Error Types）

- **认证域** (`src/features/auth/errors.ts`)：定义 `AuthFailureCode` 联合类型及对应的 HTTP 状态码映射（422/401/429/503），通过 `authFailure()` 工厂函数返回结构化失败对象，禁止泄露账号是否存在。
- **未登录错误** (`src/features/auth/unauthenticated-error.ts`)：`UnauthenticatedError` 类配合 `throwIfUnauthenticated()` 拦截器，客户端统一捕获 401 并打开登录弹窗。
- **AI 适配层错误** (`src/features/ai/provider-unavailable-error.ts`, `route-contract-error.ts`)：`ProviderUnavailableError` 表示主备 provider 均不可用（可重试），`RouteContractError` 表示路由配置矛盾（不可重试），两者都通过 `name` 属性被工作流分类器识别。

### 2. 工作流错误分类器 (`src/features/canvas/workflow-error.ts`)

`classifyWorkflowError()` 是错误处理的枢纽，按三段优先级判定：
1. **类型优先**：通过 `error.name` 精确匹配 `ZodError`、`DirectorPreflightError`、`ArtifactValidationError`、`RouteContractError`、`RetryBudgetExhaustedError`、`ProviderUnavailableError` 等，避免文案误判。
2. **文案规则**：正则匹配外部服务响应（如 StepFun TTS 402/400、quota_exhausted、missing/not found 等），归类为 `CONFIGURATION_BLOCKED`、`MEDIA_NOT_READY`、`UPSTREAM_ARTIFACT_MISSING` 等。
3. **阶段兜底**：根据 stage 名称（QUEUE/FABRICATE/RENDER/MEDIA_NARRATION）给出默认分类。

每个分类输出 `WorkflowErrorProjection`（code + message + retryable + stage + sourceNodeId），message 经过脱敏，不包含 provider 原始响应、prompt、凭据或隐藏推理。

### 3. 无栈外泄规范

- **`server/src/lib/error-message.ts`**：`errorMessage(err)` 只提取 `err.message`，丢弃 stack 和绝对路径。
- **服务端 API** (`server/src/server/api.ts`)：所有 500 响应使用 `errorMessage(err)`，完整 stack 仅写入 `logger.error`。
- **Job 执行器** (`server/src/server/job-runner.ts`)：任务失败时 `error: errorMessage(err)` 持久化到 job-store，stack 仅进日志。
- **测试保障** (`tests/worker-error-hygiene.test.ts`)：静态检查源码不得直接 `String(err)` 作为响应体，必须走 `errorMessage`。

### 4. Next.js 前端错误边界

- **根级错误边界** (`src/app/global-error.tsx`)：独立于 Providers 和主题初始化，显示 digest 参考号，提供「返回首页」和「重试」按钮。
- **未登录处理**：客户端 API 模块统一调用 `throwIfUnauthenticated(response)`，401 自动抛出 `UnauthenticatedError`，由 `useRequireLogin().handleAuthError` 打开登录弹窗。

## 架构约定

1. **错误分类与展示分离**：业务逻辑抛出自定义错误类型，UI 层通过分类器转换为人类可读且安全的 message。
2. **可重试性显式化**：每个错误分类明确标注 `retryable: boolean`，驱动前端 UI 决定是否显示「重试」按钮。
3. **跨模块依赖隔离**：工作流分类器仅通过 `error.name` 字符串识别其他模块的错误类型，避免反向依赖循环。
4. **安全优先**：所有对外错误响应必须经过 `errorMessage` 脱敏，内部调试信息仅入日志。

## 约束与规则

- 认证端点禁止泄露账号是否存在（登录失败与验证码请求统一文案）。
- 工作流错误分类器的类型判定必须在文案匹配之前执行，防止 Zod 报文中的 `required`/`invalid` 等词被误判为外部服务错误。
- Job 失败时禁止将 stack trace 持久化到 job-store 或返回给客户端。
- 熔断降级链的错误（`ProviderUnavailableError`）必须标记为可重试，因为这是外部服务故障而非配置问题。
