文档按职责分层组织：`designs/` 存放视觉系统与架构设计（以 `canvas.pen` 为 Pencil 设计的 SSOT）；`conventions/` 定义路由与工作流失败模式等编码约定；`configuration/` 记录凭据与 TTS 配置；`deployment/` 提供访问与 Runbook；`issues/` 是核心工作区，每个 ISSUE-XXX 文件对应一个可独立派发的问题，配套 `evidence/issue-NNN/` 子目录保存截图、JSON 日志与运行产物作为验收证据；`plans/` 与 `superpowers/plans+specs/` 分别存放高层计划与技术规格；`archive/migration/` 保留历史迁移证据。各目录通过 README 建立索引与依赖关系（如 `issues/README.md` 明确两套智能体系统的边界与禁止跨域修改），形成「问题→证据→修复→验证」的闭环结构。
