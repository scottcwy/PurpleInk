测试文件按功能域平铺在 tests/ 目录下，每个 .test.ts/.test.tsx/.test.mjs 文件对应一个独立 describe 块，无共享 fixture 目录，依赖通过相对路径直接 import 源码（如 ../server/src/tts/*、../server/src/compose/model）。测试分为三类：
- 契约/静态断言类：通过读取源码或 .env.example 文件并用正则断言结构不变（如 env.test.ts、app-route-contract.test.tsx、tts-pipeline-integration.test.ts、worker-error-hygiene.test.ts）。
- 运行时集成类：使用 vi.fn/vi.mock 注入 mock（fetch、ProcessRunner、fs），调用 server 侧 TTS 管线函数并断言输出（tts-runtime.test.ts、tts-orchestration.test.ts、tts-pipeline-integration.test.ts）。
- UI 渲染类：使用 react-dom/server 的 renderToStaticMarkup 对组件进行 SSR 快照式断言（cvc-ui-smoke.test.tsx、providers-theme.test.tsx）。
测试不启动 Next 服务器或浏览器，仅加载 Node/Vitest 环境，依赖方向单向指向 src/ 与 server/src/ 源码。
