脚本按职责划分为三个子目录，彼此独立、无相互依赖：
- `scripts/dev/`：Windows 专属的 PowerShell 启动器（`start-dev.ps1` + `start-dev.cmd`），按固定顺序执行工具链检查、`.env.local` 校验、Docker Postgres 拉起、pnpm install、db:migrate、Next 与 worker 进程启动及健康探针，端口冲突自动顺延并同步 `BACKEND_ORIGIN`。
- `scripts/setup/`：一次性初始化脚本，通过 `bootstrap-credentials.ts` 将 GEMINI_API_KEY / STEPFUN_API_KEY 经真实 API 校验后写入 Postgres 加密存储，`db-migrate.ts` 调用 Drizzle 应用已提交迁移，`seed-owner-account.ts` 创建初始工作区，`server-only-stub.js` 作为 Next 进程哨兵的占位模块供非 Next 运行时 dynamic import。
- `scripts/migration/`：遗留 SQLite → Postgres 的数据桥接，`export-sqlite.ts` 导出快照与制品清单，`import-postgres.ts` 基于同一 `legacy-export/import` 库反向导入，`reconcile-postgres.ts` 与 `sqlite-backup.ts` 负责对账与备份，所有源路径必须通过 CLI 参数显式传入，禁止从应用配置推导。
- `scripts/verify/`：面向 CI/CD 的验证套件，`e2e-smoke.ts` 驱动真实 HTTP API + Chromium + ffmpeg 生成 MP4 并核对产物哈希；`auth-flow-smoke.mjs` 走通人机验证→验证码签发→注册→会话→守卫→登出全链路；其余 `.mjs`/`.ts` 分别覆盖页面截图、架构基线比对、StepFun 探测等专项用例。

所有脚本遵循统一入口模式：解析 `--flag value` 参数、通过 `process.env` 读取配置、失败时输出结构化 JSON 到 stderr 并设置 `process.exitCode`，保证可被上层编排（如 Docker compose `service_completed_successfully`）可靠消费。
