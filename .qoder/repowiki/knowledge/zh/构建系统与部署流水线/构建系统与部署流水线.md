## 1. 构建系统概览

本项目采用 **pnpm monorepo**（`pnpm-workspace.yaml`）管理两个子包：根目录的 Next.js 前端应用与 `server/` 下的独立渲染 Worker。构建、测试、迁移、开发启动全部通过 `package.json` 中的 npm scripts 编排，生产镜像由多阶段 Dockerfile 构建。

- **包管理器**：pnpm@10.30.0（通过 `packageManager` 字段锁定，`corepack enable pnpm` 启用）
- **Node 版本要求**：`>=22.11.0`（`engines` 字段 + 开发脚本校验）
- **前端框架**：Next.js 16.2.0（App Router），Turbopack 作为默认构建器
- **后端运行时**：tsx 直接执行 TypeScript 源码（无预编译产物）
- **数据库 ORM**：Drizzle Kit（schema → migrations/pg）
- **测试框架**：Vitest（单测 + PostgreSQL 集成测试分离配置）

## 2. 关键文件与职责

| 文件 | 职责 |
|------|------|
| `package.json` | 根工作区脚本：dev/build/start/lint/format/test/db:migrate/typecheck |

## 3. 架构与设计决策

### 3.1 Monorepo 依赖共享
- 根 `pnpm-lock.yaml` 同时约束 `.` 和 `server` 两个包的依赖版本
- 两个 Dockerfile 都从仓库根上下文构建，复用同一份 `pnpm install --frozen-lockfile` 结果
- Worker 镜像需 COPY 根 `src/` 目录以访问跨目录引用的 TTS 配置模块（唯一一处跨包引用）

### 3.2 多阶段 Docker 构建策略
- **deps 阶段**：仅安装依赖，跳过 Chromium 下载（`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`）
- **build 阶段**：执行 `next build`，NODE_ENV=production 触发 console 移除（保留 error/warn）
- **migrate 阶段**：保留 devDependencies（tsx/drizzle-kit）供一次性迁移任务
- **runtime 阶段**：最小化运行镜像，按 playwright 实际版本安装 Chromium，非 root pwuser 运行

### 3.3 Next.js 反向代理模式
- 前端统一走 `/api/engine/*`，通过 `next.config.ts` 的 `rewrites` 转发到 `BACKEND_ORIGIN`（默认 `http://localhost:8787`）
- 生产环境 worker 不对外暴露，仅内网被 next 访问
- serverExternalPackages 将 `ffmpeg-static`、`@earendil-works/pi-*` 外部化，避免 Turbopack 动态 require 失败

### 3.4 开发环境与生产环境解耦
- 开发：PowerShell 脚本自动处理端口冲突、Docker 引擎启动、Postgres healthcheck、依赖同步、迁移执行
- 生产：docker-compose.prod.yml 严格定义服务依赖顺序（postgres → migrate → bootstrap-credentials → seed-demo-account → next → reverse-proxy）

## 4. 约定与约束

### 4.1 构建约束
- **必须使用 pnpm**：开发脚本显式检查 pnpm 版本，其他包管理器不受支持
- **Node 版本下限**：`>=22.11.0`，开发脚本在启动时校验并拒绝低版本
- **锁文件冻结**：Docker 构建强制 `--frozen-lockfile`，禁止在线解析
- **Chromium 版本对齐**：通过 `node -p "require('./node_modules/playwright/package.json').version"` 动态读取实际版本安装，避免镜像间版本漂移

### 4.2 环境变量约定
- 必需变量名在开发脚本中硬编码校验（`DATABASE_URL`、`CVC_CREDENTIAL_MASTER_KEY`），值永不打印或记录
- 可选变量（如 `GEMINI_API_KEY`、`STEPFUN_API_KEY`）缺失时功能降级而非崩溃
- 生产 compose 中所有敏感变量通过 `${VAR:?错误消息}` 语法强制设置

### 4.3 安全与运行约束
- 容器内以非 root 用户 `pwuser` 运行，Playwright 浏览器二进制存放在 `/ms-playwright`（chown 给 pwuser）
- 生产镜像禁用 source maps（`productionBrowserSourceMaps: false`）
- Next 构建移除 console.log，但保留 `error` 和 `warn` 以便诊断
- Worker 输出目录 `/repo/server/out` 和采集目录 `/repo/server/capture` 单独挂载为 volume

### 4.4 测试约定
- 普通单测：`pnpm test`（Vitest node 环境，排除 *.pg.test.ts）
- PostgreSQL 集成测试：`pnpm test:pg`（使用 `vitest.pg.config.ts`）
- E2E 冒烟测试：`pnpm verify:e2e`（调用 `scripts/verify/e2e-smoke.ts`）
- 架构验证：`pnpm verify:v3`（调用 `scripts/verify/v3-architecture.ts --check`）

### 4.5 数据库迁移约定
- Schema 定义位于 `./src/lib/db/schema/index.ts`
- 迁移文件生成到 `./src/lib/db/migrations/pg`（Drizzle Kit 输出）
- 迁移命令：`pnpm db:migrate`（tsx 执行 `scripts/setup/db-migrate.ts`）
- 生产环境中 migrate 作为独立一次性服务运行，依赖 completed_successfully 后才启动 next

### 4.6 发布与部署流程
- 单一 Dockerfile 构建 Next 应用，`server/Dockerfile` 构建 Worker
- 反向代理使用 Caddy（`deploy/reverse-proxy/Caddyfile`），唯一对外端口 443
- 凭据注入通过 `bootstrap-credentials` 一次性任务完成：env 明文 Key 经真实 API 校验后写入加密存储，运行时只读 DB
- Demo 账号创建通过 `seed-demo-account` 任务，未设置环境变量时静默退出 0

## 5. 已知限制与注意事项
- Next.js 未启用 `output: 'standalone'`，整份 node_modules 进入运行镜像（体积更大但零风险）
- Playwright 官方镜像（mcr.microsoft.com/playwright）当前 tag 404，改用 `node:22-bookworm-slim` + 手动安装
- fonts-noto-cjk 因单文件 60.2MB 在网络环境下频繁中断，改用 7.5MB 的 fonts-wqy-zenhei
- Next 启动命令必须直接调用 `node node_modules/next/dist/bin/next start`，不能通过 pnpm shim（shell 脚本无法被 node 解析）
- Worker 启动命令必须直接调用 `node_modules/.bin/tsx`（shebang 形式），不能用 `node node_modules/.bin/tsx ...` 包装
