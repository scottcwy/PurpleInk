## LV-01 — Proof First

**一句话**：先让观众看到最终结果，再用三个真实产品动作完成证明。

**参考气质**：[Linear Releases](https://www.launchvideo.com/directory/Linear)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–3s | 结果钩子 | 最终成功状态 + 一句强主张 |
| 3–7s | 旧流程摩擦 | 真实问题状态，快速切换 |
| 7–10s | 产品揭示 | Logo / 功能名，短促出现 |
| 10–20s | Proof 1 | 用户输入或触发动作 |
| 20–30s | Proof 2 | 自动处理、协作或状态变化 |
| 30–37s | Proof 3 | 最终产物、发布或数据结果 |
| 37–45s | Payoff + CTA | 三个结果回看 + 产品名 |

**视觉**：全屏真实 UI、局部裁切、暗部聚焦、细线标注、少量大字。产品状态变化与低频音效同步。

**素材要求**：3 条可验证 ProductFlow、1 个最终成功状态、品牌字体/颜色、Logo。

**不要做**：假数据、把完整桌面缩得很小、每个点击都加音效。

**适合 PurpleInk 的原因**：最能表达“Show proof before promise”，也最容易绑定来源、版本和审阅状态。

## LV-02 — One Feature Drop

**一句话**：20 秒只发布一个功能，让一个动作成为整条片子的高潮。

**参考气质**：[Square 22-second product demo](https://mypromovideos.com/video-inspirations/video/square-handheld-pos-product-demo-mixed-style/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–2s | 最终结果 | 首帧直接展示完成状态 |
| 2–5s | 功能名 | 大字 + 极短副标题 |
| 5–14s | 一个完整动作 | 输入 → 处理 → 结果 |
| 14–18s | 为什么重要 | 一句用户收益 |
| 18–22s | CTA | Logo + Try / Watch / Ship |

**视觉**：强节奏、单一背景、一个 UI 焦点、硬切与 match cut。默认做 16:9、1:1、9:16 三版。

**素材要求**：1 条 8–10 秒 ProductFlow 即可。

**不要做**：塞第二个卖点；它的力量正来自单一信息。

**适用发布**：每周更新、X/LinkedIn 首发、Product Hunt gallery、官网功能区。

---

## LV-03 — Calm Editorial

**一句话**：用安静的排版和清晰的 UI，让软件显得成熟而不是喧闹。

**参考气质**：[Notion Mail](https://www.notion.com/releases/2025-04-15)、[Notion Offline 33-second film](https://mypromovideos.com/video-inspirations/video/notion-offline-mode-mixed-style-brand-film-saas/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–4s | 日常痛点 | 留白中的一句话或一个安静场景 |
| 4–8s | 新方式 | 产品名缓慢进入 |
| 8–19s | Capability 1 | 大面积产品画面，轻微镜头推进 |
| 19–30s | Capability 2 | 用构图匹配切到第二个场景 |
| 30–40s | Capability 3 | 产品结果与用户情境连接 |
| 40–48s | 收束 | 简洁品牌句 + CTA |

**视觉**：暖白/黑/品牌强调色、杂志式排版、真实 UI、大留白、轻微纸张或界面质感。

**素材要求**：2–3 条真实 UI、少量生活化静帧或产品环境素材。

**不要做**：过快剪辑、霓虹渐变、故作未来感的粒子。

**适合产品**：知识管理、邮件、日历、写作、个人效率和设计工具。

## LV-04 — Mixed Media Product Film

**一句话**：真人负责情绪，UI 负责证明，排版和动画负责把二者连成品牌故事。

**参考气质**：[Descript 60-second mixed style demo](https://mypromovideos.com/video-inspirations/video/descript-text-based-ai-video-editing-mixed-style-product-demo/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–5s | 创作/工作中的冲突 | 真人、实物或屏幕外情境 |
| 5–10s | 产品提出新方法 | UI 与标题共同出现 |
| 10–25s | Workflow 1 | 实拍 → UI → 产物连续转场 |
| 25–40s | Workflow 2 | 图片、字卡、产品画面混剪 |
| 40–53s | 结果蒙太奇 | 多种产物和用户场景 |
| 53–60s | 品牌收束 | 产品名 + 一句定位 |

**视觉**：真人、UI、图片、贴纸、字幕、图形元素混合；风格来自 BrandKit 而不是模板默认色。

**素材要求**：真人/工作场景 4–6 个镜头、3 条 UI 流程、产品产物、较完整 BrandKit。

**不要做**：把真人素材当无关 B-roll；每个真人镜头都应说明“谁在什么情境下使用”。

**适用发布**：重大版本、新产品、面向创作者或较宽人群的软件。

## LV-05 — Release Stack

**一句话**：用一个共同命题串起 3–5 个功能，制造 Launch Week 的发布势能。

**参考气质**：[Figma Config 2025](https://mypromovideos.com/video-inspirations/video/figma-config-2025-new-launches-innovations-product-demo-figma/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–5s | 共同命题 | 一句话定义这次更新意味着什么 |
| 5–15s | Feature 1 | 独立色彩 + 代表性动作 |
| 15–25s | Feature 2 | 新章节字卡 + UI 证明 |
| 25–35s | Feature 3 | 新章节字卡 + UI 证明 |
| 35–48s | Feature 4/5 | 更短的功能连发 |
| 48–60s | Workflow union | 功能串成一条完整工作流 |
| 60–65s | CTA | 统一品牌收束 |

**视觉**：章节化、大字标题、独立功能色、快速 UI 编舞、发布会级音乐结构。

**素材要求**：3–5 条产品流程；每个功能必须有一个可视化结果。

**不要做**：超过 5 个功能；功能只是列表而没有共同命题。

**适用发布**：季度版本、年度活动、Launch Week、产品套件升级。

## LV-06 — Before / After

**一句话**：让观众同时看到旧工作流的混乱和新工作流的压缩。

**参考气质**：[Asana mixed-style brand ad](https://mypromovideos.com/video-inspirations/video/asana-workplace-silos-mixed-style-brand-ad/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–5s | Before | 多窗口、重复操作、分散信息 |
| 5–9s | 转折 | 一句“Now…”或产品揭示 |
| 9–24s | After | 同一任务在产品内完成 |
| 24–32s | 结果对照 | 步骤、时间或状态数量减少 |
| 32–38s | CTA | 新工作方式 + 产品名 |

**视觉**：左右分屏、相同构图的前后匹配、凌乱到有序、颜色从中性转向品牌色。

**素材要求**：旧流程的真实/可重建界面、对应的新产品流程、可验证结果。

**不要做**：编造“节省 80% 时间”等未验证数字；可以展示步骤减少而不虚构指标。

**适用产品**：自动化、项目管理、CRM、协作、审批和数据整合软件。

---

## LV-07 — Exact Workflow

**一句话**：不讲空泛价值，完整证明一个高价值流程从触发到成功。

**参考气质**：[OpenText CloudAlly 56-second workflow explainer](https://mypromovideos.com/video-inspirations/video/opentext-cloudally-sharepoint-recovery-mixed-style-explainer/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–5s | 高风险场景 | 一个具体问题状态 |
| 5–10s | 解决路径 | 产品功能名 + 操作目标 |
| 10–38s | 完整工作流 | 3–5 个必要步骤，不跳过关键状态 |
| 38–48s | 成功验证 | 成功状态、日志、结果或检查点 |
| 48–56s | 价值与 CTA | 谁应该使用 + 下一步 |

**视觉**：理性、清晰、少装饰；使用步骤标记、路径线、局部放大和状态徽标。

**素材要求**：一条完整且可重复的 ProductFlow、前置状态、成功断言、产品版本信息。

**不要做**：为了节奏删掉决定可信度的关键步骤。

**适用产品**：安全、备份、数据平台、财务、运维、企业基础设施。

---

## LV-08 — Developer Build Montage

**一句话**：把代码、命令、产品 UI 和运行结果剪成一次连续的“build → ship”过程。

**参考气质**：[GitHub mixed-style explainer](https://mypromovideos.com/video-inspirations/video/github-mixed-style-explainer-saas-brand-film/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–3s | Build hook | 最终运行结果或一句开发者主张 |
| 3–10s | Start | 安装、连接或创建项目 |
| 10–22s | Build | 代码、terminal、IDE、agent 动作 |
| 22–34s | Inspect | preview、log、diff、测试结果 |
| 34–43s | Ship | deploy / publish / merge |
| 43–48s | CTA | 文档入口或 Get started |

**视觉**：等宽字体、编辑器高亮、终端输出、快节奏裁切；保留真实代码，不用装饰性伪代码。

**素材要求**：命令行、代码、产品 UI、最终可运行结果；最好有真实项目仓库。

**不要做**：代码滚动过快、终端文字不可读、用 Matrix 式装饰冒充技术感。

**适用产品**：IDE、API、SDK、数据库、部署平台、AI coding agent。

---

## LV-09 — Founder + Live Demo

**一句话**：由创始人解释“为什么现在”，再用未经重画的真实演示建立信任。

**参考气质**：[OpenAI Operator](https://openai.com/index/introducing-operator/)、[Cursor changelog](https://cursor.com/changelog)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–12s | What changed | 创始人直接给结论 |
| 12–28s | Why now | 用户问题或产品判断 |
| 28–70s | Live demo | 一条真实流程，保留适度自然感 |
| 70–90s | Implication | 这会怎样改变工作方式 |
| 90–105s | CTA | 申请、试用或文档入口 |

**视觉**：人物近景、工作环境、屏幕录制、少量品牌字卡；不过度抛光。

**素材要求**：表达清楚的创始人/产品负责人、可稳定演示的产品、收音和基础布光。

**不要做**：先讲 30 秒公司使命；演示中只说不做。

**适用发布**：新品类、AI agent、新交互范式、研究能力产品化。

## LV-10 — Brand Metaphor + Product Proof

**一句话**：先用一个可记忆的现实隐喻制造情绪，再让产品 UI 证明它不是纯广告。

**参考气质**：[Okta agentic enterprise office comedy](https://mypromovideos.com/video-inspirations/video/okta-mixed-style-brand-film-agentic-enterprise-saas/)、[Asana work-anxiety mixed-style ad](https://mypromovideos.com/video-inspirations/video/asana-work-anxiety-3d-mixed-style-project-management-ad/)

**时间结构**：

| 时间 | 内容 | 画面 |
|---:|---|---|
| 0–12s | 隐喻化问题 | 真人剧情、喜剧或视觉隐喻 |
| 12–20s | 产品转折 | 品牌句 + 产品出现 |
| 20–48s | Product proof | 2–3 个真实 UI 动作 |
| 48–62s | 情绪回收 | 回到人物，问题已改变 |
| 62–70s | 品牌收束 | 产品名 + 类别主张 |

**视觉**：真人、置景、道具、动态图形和真实 UI 混合，强调独特概念而非模板感。

**素材要求**：创意概念、演员/场景、完整拍摄、2–3 条产品流程、较高后期预算。

**不要做**：隐喻与产品无关；产品在最后只露 Logo。

**适用发布**：融资、品牌重塑、进入新品类、大型年度发布。

## 我的初选建议

### 第一组：最适合 PurpleInk 产品本身

1. **LV-01 Proof First**：最能表达真实证据、审阅和可复现。
2. **LV-03 Calm Editorial**：让品牌保持精确、克制、可信，不落入泛紫色 AI SaaS 风格。
3. **LV-05 Release Stack**：能直接证明 PurpleInk 适合持续发布和多版本生产。

建议组合成一条 50–55 秒母版：以 LV-01 为骨架，采用 LV-03 的视觉系统，结尾加入 LV-05 的多渠道版本蒙太奇。

### 第二组：最值得作为 PurpleInk 首批内置模板

1. **LV-01 Proof First** — 默认产品发布。
2. **LV-02 One Feature Drop** — 高频社媒发布。
3. **LV-05 Release Stack** — 季度/Launch Week。
4. **LV-07 Exact Workflow** — 复杂 B2B 与企业产品。

### 暂不建议 MVP 内置

- **LV-09** 依赖真人拍摄与表达质量，难以由纯软件工作流稳定生成。
- **LV-10** 依赖创意概念、演员和场景，成本高且难复用。

## 选定后下一步

选 2–3 个编号后，下一轮会为每个入选模板输出：

- 逐秒旁白与字幕；
- 12–18 格镜头表；
- 每格对应的产品证据和素材要求；
- 16:9 与 9:16 构图差异；
- 动效、转场、音乐和音效说明；
- 可直接进入 PurpleInk Template Schema 的场景字段。
