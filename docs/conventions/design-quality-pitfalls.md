# 设计质感失败模式与交付自查

> Created: 2026-07-28 · Status: accepted
> 来源：2026-07-28 按钮与设置面板重构实战（第一版被用户驳回，第二版通过）。
> 读者：后续所有做 UI 视觉变更的代理。动手改任何控件/页面视觉前必读 §1、§3。

本文回答两个问题：**为什么有时会产出难看的设计**、**为什么很多东西看起来廉价**。
所有规则都附症状、根因与可执行的检验方法，可直接复制到任务提示词中作为验收标准。

---

## 1. 廉价感的六个根因（按出现频率排序）

### 1.1 外来色相：颜色不是从体系里"长"出来的

- **症状**：某个控件的颜色在整个页面里找不到同类。本案：按钮用蓝紫渐变
  `#8B9AD8→#5A6BB5`，而项目墨族 `#171A2E`、瓷白表面里根本没有紫——按钮成了外来物。
- **根因**：直接套"常见主色"。蓝紫（indigo/blue-violet）是训练数据里出现频率最高的
  按钮色，不先读项目 token 就会回退到它。
- **规则**：新颜色必须能从既有 token 族推导（同族明度迁移，不引入新色相）。全界面
  彩色色相 ≤1 个；本案唯一彩色是 `ds-blue` 信息蓝，主按钮改用墨族中性色后系统立刻成立。
- **检验**：把页面截图缩小到 32px 马赛克，数得出几种"彩色"。主彩色超过 1 种即告警。

### 1.2 渐变与拟物光影（"凸起感"）

- **症状**：控件层 135° 渐变 + 顶部内高光 + 双层投影 → 按钮像 2012 年 Bootstrap
  拟物残留，和全项目的平面语言直接打架。
- **根因**：把"高级感"等同于"加效果"。扁平体系里，深度靠**明度分层 + 发丝边框
  （hairline）**表达，不靠 drop shadow。
- **规则**：渐变只允许出现在背景层，禁止出现在控件层；控件零投影或仅发丝环。
  顶级参照：Vercel（`#171717` 实心、零投影、发丝环）、Linear、Stripe——
  "trust contrast and typography over color"。
- **检验**：问"这个效果去掉会变差吗？"答不上来就删。好设计做减法。

### 1.3 对比度不足的"水洗色"

- **症状**：白字压浅渐变（实测 2.4:1）；tinted 底与字明度相近 → 主按钮像 disabled。
- **根因**：凭目测配色，从不计算对比度；明暗两态用同一个色相拉伸。
- **规则**：控件文字对比度 ≥4.5:1，**计算而非目测**；明暗主题各自独立取值——
  本案浅色用墨色 `#171A2E`（~15:1）、暗色反转近白 `#F1F1F4`（~14:1），
  正是"按钮也要浅色和深色"。

### 1.4 雾化体系：没有一处"确定的颜色"

- **症状**：半透明 surface 叠在薰衣草渐变底上、蓝灰边框、低饱和语义色 → 整页一层
  蓝灰雾，什么都"不确定"。
- **根因**：表面靠透明叠加混色，等于把配色决定权交给了背景。
- **规则**：surface 趋实（不透明度 ≥F5）；边框中性灰而非蓝灰；背景渐变末端降饱和；
  语义色提高纯度（本案 `ds-blue #4E5FA8→#3B5BDB`、`ds-red #C4475B→#D92D20`）。

### 1.5 状态层缺失或不可感知

- **症状**：hover 仅 `brightness-105`（肉眼不可见），无 active、无统一 focus。
- **规则**：交互态至少 4 个且各自可区分——hover **换底色**（不是 5% 亮度）、
  active 下压（`translate-y-px` + 变暗）、focus-visible 统一 ring token、
  disabled 降不透明度。状态不可只靠颜色表达（文案/图标语义同步）。

### 1.6 密度节奏断裂

- **症状**：44px 行高被 11 处 `min-h-11 flex-col` 覆写撑破；14/12/11/10 四级字号挤在
  同一视觉带；面板间距 12px；容器套娃（卡片套被扒光的组）。
- **规则**：一种行一种职责——导航/只读行 48px、表单行 56px 分流（本案拆出
  `SettingsField` 原语吸收全部覆写）；字号梯度 ≤3 级且最小 12px；模块间距 ≥16px；
  容器语义不互相嵌套抵消。

## 2. 为什么 AI 特别容易产出廉价设计（元原因）

1. **默认审美回退**：不指定就走训练数据最高频方案（indigo 渐变按钮、泛用阴影）。
2. **孤立改组件**：只读 Button 文件，不看它所在画布的明度/色相结构。
   本案用户原话："项目整体颜色布局是综合性的"——单点再精致，不合体系就是外来物。
3. **效果堆叠**：渐变+投影+内高光+圆角+动画一次全上，每个 5 分、合计 0 分。
4. **不看实物**：没截图就交付。本案 v1/v2 的差距只有截图才暴露；
   "没截图不叫交付"。
5. **规范脱节**：项目 SSOT 明文写"深海军蓝、避免高亮蓝紫"，实现却漂到浅紫——
   先读权威文档再动手，改完同次回写。

## 3. 交付前自查清单（可直接复制为验收标准）

- [ ] 所有控件色都能从既有 token 族推导；全页主彩色 ≤1 种（32px 马赛克检验）。
- [ ] 控件文字对比度 ≥4.5:1，明暗两态都**计算过**（不目测）。
- [ ] 控件层无渐变 / 重投影 / 内高光（除非体系本身就是拟物风）。
- [ ] hover 换底可感知、active 有按压、focus-visible 统一 ring、disabled 可辨。
- [ ] 浅色与深色主题各自独立取值（主操作反转或重调，非同一色拉伸）。
- [ ] 截图验证：明暗双态 × hover/active/disabled × 真实路由实物图
      （登录态页面用真实会话抓，不只截 demo）。
- [ ] 字号梯度 ≤3 级；行高/间距节奏统一；无行高覆写残留（grep 验证）。
- [ ] 规范文档（`docs/designs/Design-system-inventory.md`）同次回写。

## 4. 本案三版对照（参照基准）

| 维度 | v0 原版 | v1 被驳回 | v2 通过 |
|---|---|---|---|
| 主按钮色 | 浅紫蓝渐变 `#8B9AD8→#5A6BB5` | 深海军蓝渐变 `#2B3A8C→#1F2C6E` | 扁平墨色 `#171A2E` / 暗色反转 `#F1F1F4` |
| 白字对比度 | ≈2.4:1 | ≈10:1 | ≈15:1 / ≈14:1 |
| 光影 | 单层投影 | 内高光+双层投影（凸起） | 零投影，发丝边框 |
| 色相 | 外来蓝紫 | 外来蓝紫（更深） | 墨族中性，与体系同源 |
| 主题适配 | 两态同色相拉伸 | 两态同色相拉伸 | 浅色墨 / 暗色白，各自独立 |
| 交互态 | brightness-105 不可感知 | hover 提亮可感知 | hover 换底 + active 下压 + 统一 ring |
| 截图证据 | `output/design-audit/button-*.png` | `a-button-*.png` | `v2-button-*.png` |

v1 的教训值得记住：**方向对（深色）但语言错（渐变+凸起+蓝紫）照样被驳回**。
v2 只做三件事——去渐变、去投影、色相反转归墨族——质感立刻对齐 Vercel/Linear。

---

## 5. 一句话原则

1. 颜色从体系里长出来，不从调色板里挑出来。
2. 扁平体系的深度靠明度分层，不靠阴影。
3. 每加一个效果先问"去掉它会变差吗"；答不上来就删。
4. 浅色深色的按钮各自配色，不是一个色相两头拉。
5. 没截图不叫交付。
