## 4. 合并与 provenance 规则

1. 内容按责任批次审计、移植、验证和本地提交；不得直接把 dev 或 penguin 整体内容 merge 到 `predev`。
2. 每批只 stage 该批文件，提交前记录 staged 文件清单、验证命令与结果；失败或未执行必须原样保留。
3. 某来源的全部已接受内容完成后，才允许追加该来源的 provenance ours merge。该 merge 只记录祖先关系，不得改变文件树。
4. provenance merge 的第一父提交 tree hash 与 merge commit tree hash 必须完全相同。合并前可记录当前 tree 供审计；合并完成后必须以 `HEAD^1` 重新取得第一父 tree，并与 merge commit tree 比较：

   ```powershell
   git rev-parse 'HEAD^{tree}'
   git merge -s ours --no-ff <完整来源SHA>
   git rev-parse 'HEAD^1^{tree}'
   git rev-parse 'HEAD^{tree}'
   ```

5. `git rev-parse 'HEAD^1^{tree}'` 与 `git rev-parse 'HEAD^{tree}'` 的结果不同即视为失败：不得继续下一来源、不得用后续提交掩盖差异。ours merge 也不能替代内容批次的文件级 provenance、测试和审查。
